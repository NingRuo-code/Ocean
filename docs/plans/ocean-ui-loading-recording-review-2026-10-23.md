## 6. 算法推进建议：先分解，再选择

此表补足 #17 的实验候选，不把全部候选预先承诺为必做。

| 阶段 / 实测瓶颈 | 具体候选 | 选用与验证条件 |
| --- | --- | --- |
| 优先正确性与测量 | 完整请求身份、序号/取消或过期隔离；按数据/方法版本失效缓存；分阶段计时 | 同窗口换日、快切范围、乱序、失败重试及版本变化不串结果。正确性检查不等性能排序。 |
| 重复请求、传输过大 | 保留视野 LOD，复用窗口/规则瓦片，有限邻日预取，全日期 LRU/内存预算 | 请求数、字节和峰值内存改善；概览分辨率有提示，分析数据不被粗化替换。 |
| 重画/面板计算卡顿 | 图层增量更新、路径/投影缓存，隐藏面板按需计算；必要时 Worker | 相同操作比较绘制耗时与长任务，数值/几何/选中态不变。Worker 不自动解决所有 DOM 绘制成本。 |
| 最近锋面等空间搜索慢 | 包围盒/线段空间索引先筛候选，再做精确距离 | 与完整扫描对照，边界和最近对象一致；索引本身不替代精确距离。 |
| 月/年扫描慢 | 可复用逐日基础汇总、时间前缀和，分块/规则网格聚合；圆形边界精确处理 | 仅对可加基础量与相容固定条件复用；小时数、有效面积和天数分别保存，不能均值再平均或把缺测补零。 |
| 多视图联合筛选聚合慢 | 列式分析/预聚合或多维索引小原型，对照朴素扫描 | 多视图确为核心且聚合确为主耗时才启动；同时记录构建、传输、内存、更新和误差。 |
| 绘制仍占主要时间 | 对比 Canvas/WebGL；活动概览用屏幕网格 SUM 聚合并支持细节查询 | 显示聚合保留总小时数；科学统计独立用完整数据。新技术需给出实际收益与维护成本。 |

imMens 作者论文页说明其采用分桶、多变量数据瓦片和 GPU 查询/渲染：[官方论文说明](https://idl.uw.edu/papers/immens)。据此结合本项目任务作出工程判断：可以借鉴分桶和按视觉分辨率控制规模；任意公里圆、锋线缓冲、有效覆盖和事件研究仍需独立方法，不把完整 GPU 立方体作为全部分析的必经步骤。当前代码没有完成 imMens GPU 立方体复现。

测量场景：冷/热首屏、换日、换点/半径、图层开关、连续拖缩/播放、月度分析；局部/区域/全球视野及不同数据规模。记录重复次数、设备、网络、提交与资料版本；报告 p50/p95、请求数/字节、服务端读算、传输、解析、适配、绘制、面板、长任务和可测资源。具体时间门槛依基线与使用需求确认，本次不声称加速倍率，也不据录音直接购买服务器。
