## What to build

使用者读取一个比较快照时，先看到候选并列表、同单位主图和简短差异/不足，再展开A/B分板、支持及来源；允许导出的聚合成果与显示一致且没有隐含排名。

每项贯通显式确定性/受控请求、既有快照消费或同合同组合到可读结果/证据，并在本项核对独立小例与边界。复用A/B/P0基础，不新建测试专用业务接口或第二科学计算引擎；真实资格、真实比较与合成验证分开记证，不提交原始AIS、受限细网格、凭据或私人路径。

## Acceptance criteria

- [ ] 消费同一个C结果，提供可独立阅读的区域/公里范围示意、并列证据表、分板图和摘要，稳定ID对应名称；复用已有产物模式，不重算科学值或重做地图框架，完整工作台联动归#21。
- [ ] 相同指标统一单位、坐标/标尺与颜色含义，数量编码使用适当基线；不同单位分图/分列，局部增强或不同尺度显式标注，不做独立自动拉伸误导或无含义雷达综合优势图。
- [ ] 保持候选提交顺序，不按活动/效应自动排序，不出现分数、星级、成功概率或推荐名次；短解释只说可观察差异、证据完整度与局限，不推因果、鱼量或收益。
- [ ] 未知/未准备/失败/有效零、不可比和区间退化清楚表达，不画假零柱、补缺曲线或新显著标签；展开每格支持、候选/排除/对照/相关组及源身份，缺项不隐藏候选。
- [ ] 图表、摘要、允许聚合导出与运行清单共享比较身份、政策/方向/条件和版本，公开内容逐源核许可，不输出受限细表或私人路径；完整PDF/案例保存不在本项重建。
- [ ] 用同一结果核对表/图/摘要/导出、同标尺、部分失败与候选顺序及来源一致；正式浏览器工作台由#21后续验收，真实同源消费在C09复核。
