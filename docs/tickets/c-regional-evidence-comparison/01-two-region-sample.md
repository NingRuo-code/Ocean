## What to build

使用者显式提交两个不同固定区域及共同条件，读取合法已知快照并得到可读并列表、原条件和来源身份；作为后续比较规则与A/B实际消费共同扩展的最小完整流程。

每项贯通显式确定性/受控请求、既有快照消费或同合同组合到可读结果/证据，并在本项核对独立小例与边界。复用A/B/P0基础，不新建测试专用业务接口或第二科学计算引擎；真实资格、真实比较与合成验证分开记证，不提交原始AIS、受限细网格、凭据或私人路径。

规格用户故事：1、2、3、4、5、6、31、35、36、37、38、41、42。

## Acceptance criteria

- [ ] 增量复用现有确定性查询/受控结果消费模式，提供明确C用途和实际可调用的比较/读取流程，贯通请求→合法快照→已知并列表→证据；最小兼容适配随本项完成，不做宽泛重构或新建测试专用业务接口。
- [ ] 请求包含至少两个不同点/公里圆、稳定候选ID与名称、共同半径、月份或事件搜索期、证据用途、支持政策及源身份；非法或完全重复的区域明确报错，不靠改名伪造第二候选，不悄悄合并或替换。
- [ ] 按提交顺序显示已知指标、单位、实际条件和来源，A月度与B事件用途明确分开，区域名只作标签；样例不引入推荐排名、评分或保证性渔业结论。
- [ ] 全程只读取标注合法的已就绪样例快照，不启动A/B原档分析、归档准备、下载或模型；缺少结果返回具体前置，样例和真实研究身份分开。
- [ ] 绑定提交与比较身份，改条件/增删候选后不把旧结果标成新条件，普通读取不执行重任务；每个源结果的许可和受控访问边界分别保留。
- [ ] 输出最小可独立阅读的结果及证据，不依赖完整工作台或AI，旧单点历史频次/响应查询保持原用途；未具备A/B生产适配时不称真实比较已完成。
- [ ] 以两区、重复/改名、月份或半径不符、缺结果、零/未知和改条件小例，从真实入口独立核对区域身份、原值/单位、状态和读取副作用，不用被测比较器生成预期。
