## What to build

维护者在隔离环境激活一套完整兼容发布，使用者读取实际新版本；旧标签页或旧缓存不悄悄按新合同重放请求。

每项沿实际发布/备份/恢复操作→原服务与真实浏览器/API→同身份任务/结果/文件验证自身完整行为，辅助独立小例、内容/权限核对及受控故障，不为测试新建业务系统。真实成果/模型、已知样例、合成故障、隔离环境与生产分别记证；生产操作须后续已有审核和单独安排，本轮拆票不授权部署、采购、清理或模型费用。凭据、真实主机地址/个人路径、受限源档/细AIS及原始敏感日志不进入公开产物。

## Acceptance criteria

- [ ] 从预检、包完整性/暂存、环境和格式检查、隔离冒烟到激活/入口核验和持久发布记录贯通；先限定无状态迁移或已兼容的已知读取/最小写入类型，活动长任务升级由O05补足。
- [ ] 前端、静态资产、API与执行进程实际加载身份可核，入口能发现新版本、内容资产按身份复用；磁盘代码替换不能冒称进程已更新，静态缓存不混新旧版。
- [ ] 旧页面/工具合同不兼容须停止受影响新提交并提示刷新，不自动改条件、重放旧意图或把原结果放新标题；后端源/方法/权限缓存沿原合同，不清空全部缓存掩盖错配。
- [ ] 发布阶段/结果可靠记录并防并发互相覆盖，重复或响应丢失先核实际激活状态；失败不切换/不出现半套配置，上一可用入口和已完成成果保持可读。
- [ ] 页面仅给必要短状态/按需信息，观测日、源处理、构建/激活和结果时间分开，原地图框架和离线兜底保留；维护期间哪些操作可用真实说明。
- [ ] 用两套实际可区分发布和独立查询期望，在真实浏览器/API核正常激活、旧标签页/缓存、丢响应/并发、缺资产/进程未更新与失败不切换；不触碰生产或以一次health200代替。
