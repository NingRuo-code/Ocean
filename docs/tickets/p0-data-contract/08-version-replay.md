## What to build

维护者重跑审计或替换数据/方法后，查询得到相应版本的支持判定，旧快照仍能识别，过期缓存不沿用错误资格。

每项均复用现有显式审计入口，交付可观察报告或可查询的支持结果，并包含自己的自动验证和可复算小例；不把数据结构、读取、API或测试拆成脱节的横向任务。合成夹具与真实资料分开记证，不提交原始 AIS、受限细网格、凭据或私人路径；未执行的检查不填通过。

## Acceptance criteria

- [ ] 同输入与协议重跑保持实质身份和结论稳定，生成时间单列；不因时间戳而把同资料伪装成新源版本。
- [ ] 源内容、处理、几何/质量规则或参数版本变化时产生可区分结果身份；旧记录保留来源，不原地伪装成新证据。
- [ ] 支持查询和缓存按条件及必要版本隔离；旧响应、扫描中的半成品和失配快照不能覆盖当前有效资格。
- [ ] 缺少可靠当前身份或源无法访问时表明新鲜度未知，不复用为已验证研究资格；无需为此实现完整后台任务中心或服务器重启恢复。
- [ ] 对同输入重跑、相同路径源变化、同资料规则变化、旧快照/缓存及失败中断作端到端回放，验证报告与API一致、没有静默换条件。
- [ ] 证据保留运行范围、版本、失败/未核项和复算限制，不引入全量归档扫描作为普通请求的隐式代价。
