## What to build

维护者显式审计一个已登记来源或小样本，得到可读报告：资料角色、来源证据、版本身份、许可待核项和当前能证明的范围；后续切片复用同一入口与快照。

每项均复用现有显式审计入口，交付可观察报告或可查询的支持结果，并包含自己的自动验证和可复算小例；不把数据结构、读取、API或测试拆成脱节的横向任务。合成夹具与真实资料分开记证，不提交原始 AIS、受限细网格、凭据或私人路径；未执行的检查不填通过。

## Acceptance criteria

- [ ] 复用已有本地审计、清单与索引，先贯通输入读取→来源登记→版本化快照→可读摘要；所需小范围整理先在本切片完成，不要求另建数据库或先做全站重构。
- [ ] 登记锋面、SST、活动及旧响应表的产品/渠道、单位、研究真源/展示/预计算角色、来源到产物关系；缺项保留未知或待核实，不猜测。
- [ ] 记录源/产物、处理和合同身份、输入证据及生成时间；清单声明、可读、语义核实与有效支持分级，不以元数据齐全宣称研究就绪。
- [ ] 登记已存在的许可标记冲突、引用证据与可用边界；按具体产品/渠道核实，证据不足不自动批准公开发布或将某段代码常量当真实授权。
- [ ] 首次运行同时盘点实际可读来源和访问缺口，使缺少真源或服务器证据尽早暴露；合法可读资料可记录初始证据，无访问条件时如实列阻塞，合成输入只验证合同。
- [ ] 快照区分内部定位信息和可公开摘要，不含受限源记录；显式审计才扫描，重复读取快照不隐式重扫。验证正常、未知、声明缺字段、冲突和无法访问路径。
