## What to build

使用者按有真实支持的事前活动检索，能核对时间窗和H/E，并知道哪些历史响应只能作为后见的回顾性信息。

每项沿真实浏览器操作→实际服务/同一受控计算→候选、原证据或短窗图示验证自己的完整行为，自带独立已知小例和边界核查；辅助API核数值、身份与权限，不为测试新建业务入口。前期仅开放明确合法探索允许库，真实目录/响应/匹配与合成故障分开记证，不提交受限源档、细网格、凭据或私人路径。

规格用户故事：9、10、11、12、18、22、23、26、50。规格验收追溯：I04.3、I06.1、I06.2。

## Acceptance criteria

- [ ] 消费#71交接的合法逐日聚合/H/E和支持，沿同一特征加工/检索通路登记事前活动窗、截止日期、区域、分母/单位、版本和缺项，不以完整目标月代替事前量。
- [ ] 前期聚合只使用已声明窗和共同支持，同支持与不同支持区分；有效零与缺测分开，未经确认不得用未知记录填零或新开一套活动分析引擎。
- [ ] 参考日期、观测日、候选锚日、响应窗结束与首次可用时间分别表达；后窗跨越参考截点或可用时间未知，禁止标为当时可知，回顾性查看明确标后见/未知。
- [ ] 未来响应不参与特征/选择，不能为补足样本隐去后见标记，也不将历史案例参考改名实时作业或预测回测；历史首次可用时间无法核实就保留限制。
- [ ] 从浏览器配置到实际事前特征、候选和详情核单位/H/E/日期，使用独立手算小例覆盖零/缺日、越界窗口、月内未来、未知发布时滞及跨年，不触发A重算或准备归档。
- [ ] 真实事前特征取得与合成截点边界分开留证；资料不足时可退回明确环境检索，不能称已实现事前活动功能或已验证预测增益。
