## What to build

用户点击捕捞活动后，地图与当前结果展示所选日期、分析圈内有依据的 AIS 表观捕捞活动小时数、资料限制及邻近锋面事实。

每项均通过现有浏览器入口验证自己的完整用户流程，按影响运行数据、交互与布局检查；同步更新已被本项改变的旧断言，保留仍适用的地图回归。记录实际结果和代表性截图，不以受控响应证明真实线上覆盖，不提交受限源数据。

## Acceptance criteria

- [ ] 从快捷入口进入活动任务，复用已就绪活动资料和唯一条件；离线或当日不可用时明确原因，不生成演示热点。
- [ ] 主数值来自完整可用输入在所选范围的确定性汇总，说明来源、日期和当前展示粒度；若完整性或圈内支持不足，降为明确的部分/未知状态，不伪称总量。
- [ ] 不从分位筛选后或700点截断后的可见圆点反算活动总量；地图若仍有旧截断，明确其显示限制与后续全量任务，统计也不能宣称已修复全域资料。
- [ ] 一句简短分析、一个主数值及两至三个指标；邻近锋面位置事实与同日条件一致。改变条件后不能把旧详细结果当新结果。
- [ ] 有效零与未知覆盖/无记录/失败使用加载任务的统一状态；多船累计可超过24小时，表述为 AIS 表观捕捞活动而非渔获、鱼群密度或成功概率。
- [ ] 用可合法使用的小样本和独立汇总参照核对时长、范围边界、零及缺口；明确展示网格不能替代 ADR 要求的缓冲研究真源。
