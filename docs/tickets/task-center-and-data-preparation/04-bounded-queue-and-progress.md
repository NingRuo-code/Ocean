## What to build

本人连续提交小范围任务时，系统按有据限额执行，其余显示等待原因；可见真实阶段和已完成单元，地图轻量操作保持可用。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

## Acceptance criteria

- [ ] 在T03实际准备和既有A受控任务上增量建立有界调度，统一任务/步骤记录和登记恢复能力；不重建#99幂等受理，不引入任意工作流/脚本执行或默认分布式集群。
- [ ] 消费#47分层工作集/可核实环境清单，设显式有界重任务并发、等待数量、请求规模、暂存/磁盘余量及必要内存/网络限制；实测、保守试验值与现服未知项分开，未等完整P1也可在受控环境验证。
- [ ] 浏览器显示排队/等待资源、执行阶段、已完成单元及可靠总量，未有总量不造百分比；每次任务/步骤变化持久有序，读取进度不扫描归档或启动执行。
- [ ] 资源不足明确等待或拒绝新任务，等待不占执行额度；资源释放后按登记策略继续，超出范围/永久错误不无限重试，不以静默清理源/重要成果或扩容满足准入。
- [ ] 后台工作与地图轻读隔离预算，关闭面板/网页不改变队列意图，浏览器断网不转任务失败；复用当前合法产物读取，个人状态和日志仍受服务端授权保护。
- [ ] 在隔离受控环境从单任务到低并发真实提交，核对受理数、实际同时执行数、等待/释放顺序、阶段/产物和地图请求；记录环境/峰值/停止条件，不对生产压测或宣称服务器配置及3/1/2秒达标。
