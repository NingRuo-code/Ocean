## What to build

本人在工作台选择系统登记的日期、地域、资料层和用途，得到可读准备计划、复用范围和缺少的前置；预览不取数。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

规格用户故事：5、10、22、23、24、25、26、27、44、45、47、50。

## Acceptance criteria

- [ ] 沿#99真实能力/授权/规范化请求与P0来源身份，复用现有清单、准备计划和登记工具，打通浏览器选择→实际服务轻量计划→范围/缺项说明；必要最小适配随本项完成，不先做宽泛重构。
- [ ] 逐产品核登记、归档可访问、凭据可用、连接器/本地处理能力、许可与当前源身份；注册表示例、脚本提示命令或旧job日志不标为可执行，未知/缺能力原因明确且不可提交执行。
- [ ] 请求明确源产品、观测日期范围、区域、所需层、用途及处理目标，显示已有同版本可复用单元、待准备单元和资源估计/未知项，不沿旧默认值自动选全历史/全球。
- [ ] 不接受任意URL、文件路径、命令或用户脚本，实际归档位置由服务端登记解析；未登记/无授权/缺源版本或费用条件不默认放行，不自动申请凭据或改用另一SST/活动产品。
- [ ] 预览仅消费已有清单/资格，不扫描全档、下载、加工、研究或调用AI；在W最小合同上为后续明确提交形成冻结计划，改地图条件不改已受理计划。
- [ ] 使用合法已登记归档清单，经真实浏览器核对正常/未知/缺凭据/无连接器/越范围和本人/访客，验证实际计划身份与零执行副作用；实际准备在T03，预览完成不冒充就绪。

## 实施顺序

复用服务端登记清单的产品 ID、凭据方式和覆盖字段，以及 P0 指纹的版本表示。先验证受控清单的本人预览、同版本复用和逐项前置，再接工作台入口。已有仅供示例的登记可查看其缺项，现有扫描型运维计划保持原入口。正式准备与加工从 #112 开始。

## 本机验证

- 本人预览消费现有服务器登记清单约定。可输入登记产品、观测日期、区域、资料层、用途和处理目标。返回冻结计划、已登记同版本复用产物、待准备或受限单元及资源估计。
- 示例清单只提供选择与缺项。实际凭据存在和保存的核验证据分开。归档、连接器、处理能力、许可、费用和版本逐项判断，客户端不能提交路径、URL 或命令。
- 实际浏览器通过本人正常预览、源版本未知、凭据缺少、连接器不支持、越范围和窄屏核查。无取数、写入或分析调用。执行由 #112 承接。
- 可准备需配置 OCEAN_OWNER_PREPARATION_REGISTRY_PATH 和 OCEAN_OWNER_PREPARATION_MANIFEST_PATH。清单绑定登记原字节和现有 August 成员核验目录，预览核对已记录的成员、实际锋面适配代码指纹及许可和费用证明引用。当前仅接通 Zenodo 锋面这一已知适配，示例及其他产品保留缺项。
- 新增准备的凭据、连接器或费用缺项会阻断待准备单元。经授权且在两个清单中身份一致的既有产物可独立复用。登记撤回使原计划身份变化，错误回执不反射路径或凭据。
