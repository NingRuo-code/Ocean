## What to build

多个准备任务请求相同资料时，可复用已校验的同版本单元；取消一个或旧进程迟到，不会覆盖、删掉其他任务的有效输入。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

规格用户故事：10、13、17、27、29、30、31、34、35、39、40、43、44、48、49、50。

## Acceptance criteria

- [ ] 汇合T09多单元、T06提交所有权与T11使用/保护合同，对真实准备请求建立精确源内容/处理目标及支持身份的单元复用；不重复建P0审计或新的缓存系统，不仅以日期/路径/大小判断。
- [ ] 同一意图继续幂等，不同任务引用合法已提交单元时各自保留原请求、权限和进度；同时竞争未完成单元通过同一权威所有权/提交合同裁决，等待/复用原因在浏览器可读。
- [ ] 源同路径换内容、远程版本未知、方法或授权变化不得命中旧身份；旧就绪资料/研究结果按原版本保留，新版本与旧任务不串用，不自动扩展下载范围。
- [ ] 取消一个准备任务不删除其他任务/成果仍引用的产物，失权旧进程不能替换共享正式产物；暂存清理限各自所有权，活动/保存引用通过T11持续保护。
- [ ] 逐源许可/公开资格不因共享物理文件而合并授权，私人来源不能通过公开任务泄露；完成仍只提示实际就绪，不触发分析。
- [ ] 至少一份实际已就绪合法单元和一份实际新增单元，通过浏览器/服务验证相同及部分重叠任务、并发等待、取消其一、重启/迟到提交、同路径换源；独立核对实际处理/发布次数、引用与产物内容，合成边界另记。
