## What to build

负责人得到任务并发、准备范围、磁盘/暂存及保留规则的实测限制和未验证范围，能让配置生效而不盲目扩容或损坏地图可用性。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

规格用户故事：20、21、24、28、37、38、39、40、41、42、43、45、48、49、50。

## Acceptance criteria

- [ ] 复用#53首轮地图/重任务容量结论及其#47/#50祖先预算，与T12实际共享准备、T13保护清理汇合；不重做P1性能/论文实验，也不把本项设为所有TASK基础功能的前置。
- [ ] 在冻结环境、资料/任务规模、冷热及低并发混合负载下测实际后台单元、RSS/CPU、磁盘展开/暂存/产物/缓存增长及地图轻读表现，记录停止条件；公开生产不未经安排压测。
- [ ] 按实际工作集冻结可生效的并发/等待数、单次范围、磁盘余量、暂存/普通大产物预算与保留/清理阈值，记录数值、策略版本、推导与告警/拒绝行为，不能只限制文件数或把压缩字节当内存。
- [ ] 原档、热输入、派生/索引、P1缓存、任务结果、暂存、保护成果与备份分别核算，保护引用优先于普通清理；无可安全释放空间时明确拒绝新任务，不自动采购、迁移或删源。
- [ ] 用实际服务验证配置生效后的排队/超额拒绝、资源释放、保护保留、字节回落及地图读取，结果身份/数值不因限额改变；复用P1数据与协议，新增测量只覆盖TASK实际增量。
- [ ] 缺现服权限/真实配置时交受控测量和明确缺项，不给现服准入通过或最低购买配置；本地/测试/现服和部署证据分开，生产准入未满足保持欠项，功能回放T15不因此被假定失败或达标。
