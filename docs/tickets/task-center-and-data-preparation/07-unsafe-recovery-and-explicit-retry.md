## What to build

源、方法、授权或检查点不再满足恢复条件时，任务明确中断；本人可看到原因并按既有合同重试或提交新版本，不发生静默换源。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

## Acceptance criteria

- [ ] 扩展T05安全检查到当前实际支持的任务类型/阶段能力目录，逐项登记可恢复单元及不支持原因，不把恢复框架完成当所有A/B/C或未来预测都已支持续跑。
- [ ] 真实处理源同路径变内容、方法/几何/质量版本变化、检查点损坏/缺失、源不可得、许可/执行授权撤销及外部副作用不明时拒绝继续，浏览器显示中断原因和所需前置，不扩范围或自动准备资料。
- [ ] 复用#102明确重试的原任务/新尝试关系、幂等与版本核对，冻结输入可得才称原条件重试；本人选择当前资料/新条件需明确新请求，不重新标注旧结果，不自动循环重分析。
- [ ] 浏览器会话过期与服务端执行授权撤销区分，前者只限制读取/新操作，不能意外中断已受理合法后台任务；当前服务凭据不可用、策略变化按实际任务阶段记录原因且不外露凭据。
- [ ] 恢复状态未知、等待资源、失败和不可恢复中断分别呈现，旧成功结果保留原身份和限制，原样复算无法保证时直说；历史读取/刷新不重扫归档或发起重试。
- [ ] 以真实业务阶段及隔离源/检查点/授权变化验证安全拒绝、明确重试、同意图重发与新源请求，独立核对实际执行次数和身份；合成边界与实际进程中断/资料证据分别记证。
