## What to build

进程在发布结果与回写完成状态之间出故障时，恢复后仍识别已有成果；旧执行者迟到提交不会覆盖权威结果或重复发布。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

规格用户故事：11、12、13、16、17、30、34、35、48、49、50。

## Acceptance criteria

- [ ] 沿T05实际准备/分析提交路径收敛可靠产物提交标记与任务状态对账，不另建发布服务；处理校验通过但未提交、产物已提交但完成记录未写入及状态重放，只有验证成功的提交可作为完成依据。
- [ ] 已提交产物绑定原输入/支持/处理及结果身份，恢复检查命中后补齐权威状态/引用，不重新执行已核验步骤、重新下载或二次对外发布；不确定外部副作用不得盲目再做。
- [ ] 同一任务的恢复执行代次与失权旧执行者必须在状态和实际产物写入两处受到约束，不能只保护数据库状态却允许旧文件替换；失权写入明确拒绝并留脱敏记录。
- [ ] 原子提交区间与失败残留保持隔离，断电/异常后没有完成标记的半成品不可读，旧有效版本不被移除；完成后浏览器继续显示同一结果/原条件，不倒退为假运行。
- [ ] 不承诺任意网络副作用或外部计费exactly-once，无法确认已执行与否标中断并给原因；有限内部重做仅限未提交安全单元，不能重复已验证完成步骤。
- [ ] 隔离环境真实故障注入覆盖校验/发布前后、提交后状态回写前和旧进程恢复通信后的迟到写入，核对实际产物/发布次数、状态序列及独立内容；不以只模拟HTTP乱序代替执行者竞争。
