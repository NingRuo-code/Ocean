## What to build

真实业务执行进程重启后，已受理任务核对检查点并自动继续安全的未完成步骤；本人看到恢复起点与原条件，已完成步骤不重复。

每项沿已确认真实浏览器→实际任务服务/执行进程→持久状态/产物→同身份结果接缝验证自身完整行为，辅助API/数据核对。复用W与P0/P1合同，不另建科学引擎或伪造执行；真实处理、合法已知样例及合成故障分别记证，破坏性故障与清理仅在隔离受控材料验证，不提交受限源档、细网格、凭据或私人路径。

## Acceptance criteria

- [ ] 复用#100重开/中断观测与T04真实步骤执行，对至少一类当前实际业务登记安全恢复单元与依赖；用T03真实准备步骤或已有A计算适配，不造只为测试存在的假任务类型。
- [ ] 可靠检查点包括原意图/任务、输入内容/支持、处理/方法身份、已校验产物、完成单元及必要随机状态，输出校验和持久提交后才标完成，不能仅按路径/mtime/日志success跳过。
- [ ] 启动时核原执行授权、版本、检查点、产物及取消记录，符合条件自动继续原任务，内部执行代次/恢复尝试留记录而不新建用户提交意图；不重新执行已核验完成步骤。
- [ ] 恢复执行者必须取得权威执行所有权，状态/产物提交核当前代次或等价约束，旧执行者失权后不可覆盖；不只靠心跳超时就并发复制，提交竞争的完整故障扩展在T06。
- [ ] 浏览器显示恢复时间/起点/次数、原条件及真实阶段，关闭或登录会话过期不撤销已受理执行授权；显式撤销/许可变化阻止继续，资源暂不足等待，不因浏览器重新打开触发恢复。
- [ ] 缺检查点、身份无法核实或类型不可恢复时保留记录并如实中断，最低拒绝保证随本项完成，不为通过而默认所有任务可续跑；细分不安全恢复与明确重试在T07扩展。
- [ ] 隔离环境对实际服务/执行进程在排队、可靠步骤提交后及处理中真实终止再启动，独立核对步骤账本/输出、原任务、自动继续与未重复完成单元；有一次真实安全续跑证据才通过，不用前端模拟状态代替。
