## What to build

本人从浏览器明确提交一个小型合格A任务，服务端真实受理、执行并返回可查询的任务和结果；访客被拒绝，重复发送同一提交意图不会增加任务。

每项沿已确认真实浏览器→受控服务→任务/结果→同源证据接缝验证自己的可观察行为，并辅助API核对。复用#24及A/B/C确定性合同，不另建科学引擎或伪造执行状态；真实资料、合法已知样例和合成故障分别记证，不提交受限源档、细网格、凭据或私人路径。

规格用户故事：6、8、14、15、17、18、19、20、21、28、40、43、44、47、48。

## Acceptance criteria

- [ ] 复用#70及其A/P0前置的受控计算、资格/版本和只读结果合同，用同一个实际A计算适配完成浏览器提交→服务端受理→执行→结果读取；合法已知小例可先验，不另造假业务计算器或要求先有真实A/#71。
- [ ] 补齐或接入最小本人服务端访问边界，浏览器提交、状态和结果访问由服务端核权限/归属；前端隐藏按钮不是授权，访客可继续已公开结果轻量读取，直接越权请求不创建任务、不泄露私人条件或日志。
- [ ] 受理前复核任务类型、固定几何、年月、主方案、实际P0用途资格、源/支持/方法版本及有界执行预算；不合格不受理、不准备归档或换源换月，预检后变化也不能沿用旧放行。
- [ ] 一次明确点击就是提交意图，不另弹重复确认卡；服务端持久保存提交意图身份及任务关联，重复意图返回同一受理记录，不仅靠禁用按钮防双击；有意重算与读取已有合法结果明确区分。
- [ ] 持久任务记录至少含所有者、规范化请求、受理时源/支持与版本、状态/阶段、失败/中断原因和结果引用，任务/意图/结果身份分开；受理成功须记录已可靠保存，不靠浏览器内存或加工日志冒充。
- [ ] 计算运行不依赖页面继续打开且不阻塞地图轻量读取，采用现有设施能承载的最小有界执行；仅展示服务实际支持的排队/运行/阶段，无总量不伪造百分比，校验成功后原子发布完整结果，失败半成品不可见。
- [ ] 受理后如源身份改变、输入失效或无法再核实，保留原记录并中止/拒绝或要求显式新请求，不悄悄换条件；有限描述、成功受限结果与执行失败分开表达。
- [ ] 通过真实浏览器及实际服务，以合法已知A小例、本人/访客、双击/同意图重复发送、预检后资格变化和执行失败核对受理次数、持久状态、同源值和只读副作用；小例与真实整月执行验收分账。
