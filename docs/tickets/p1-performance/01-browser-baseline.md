## 用显式样本运行受管服务测量

用现有命令直接启动回环原服务，并在新建的缓存和数据目录内测量。将 `sample_root` 设为恢复副本的 `data/raw`，将 `report` 设为样本目录之外的全新文件。

```bash
node tools/benchmark-map.mjs --isolated-service --sample-root "$sample_root" \
  --runs 5 --timeout-ms 12000 --out "$report"
```

受管服务从本次复制的单日 NetCDF 读取数据。入口识别 `front/<year>/front_locationYYYYMMDD.nc` 和 `sst/<year>/sst_YYYYMMDD.nc`，支持至多 128 份文件、128 MiB。报告记录两层文件数、字节数及绑定文件相对位置、长度和 SHA-256 的快照身份。输出不含样本路径或原档内容。临时服务结束后释放本次副本和缓存。

受管服务在开始浏览器计时前，最多等待 45 秒取得健康响应。省略 `--sample-root` 时仍可用原空数据场景复测。显式样本用于 B0，完整覆盖和 B1 继续按实际证据核实。

## 部分视窗的可见反馈

`first_partial_paint_ms` 单列记录当前动作的日期与视窗已有可用部分数据时，首次经两帧确认的耗时。只在计时预算内接受同一文档、日期和视窗两次一致的部分状态；无可用数据、旧日期或超时观察不产生该字段的数值。从每种动作的 `partial_paint_observations` 可看到有多少次出现了这种反馈。部分结果仍不属于完整就绪，不进入原成功 p50/p95，不放宽 B1 或实际覆盖要求。

以 `bd17008` 的测量代码在 Windows 本机回环服务复测 8 份锋面和 3 份海温，共 10,838,881 字节，与此前样本指纹相同。Edge 157 使用 GPU 渲染，视窗 1440 × 900、DPR 1。服务初始缓存为空，其后由三轮共用，系统存储缓存未控制。12 秒预算内，15 次均观测到部分绘制，完整就绪仍为 0/15。每种动作三次观测到的部分绘制范围为：导航 937–1,766 ms、刷新 733–1,004 ms、换日 652–942 ms、缩放 583–717 ms、拖动 536–567 ms。这样的少量样本不产生完整成功分位、稳定尾延迟或目标达成结论。

受控浏览器反例复现了两帧间从部分转为完整时会提前计成功的问题；修复要求完整状态也必须在两帧前后均成立，并保持同一文档、日期和视窗。全量工具及浏览器回归 259 项、最终定向测量与原服务测试 17 项、数据检查 922 项通过。离线地图五类动作均完整就绪，未计为部分覆盖。
