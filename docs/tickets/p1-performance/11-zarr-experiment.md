## What to build

在有限多年样本上比较原NetCDF与两种目标分块布局，判断Zarr是否改善实际时空读取的综合成本。

任务类别：条件性。本项为条件性实验：先核对进入条件，成立才执行限定小样对照；不成立则交付有据的延后/不采用决定。决策完成不等于候选技术已实现或整项性能工作已完成。\n\n进入条件：实际多年时空读取有瓶颈，存在合法可核实的相应样本和明确查询负载。\n\n每项均交付一条可运行、可观察的完整用户流程或端到端测量/决策链，并包含自己的正确性参照、实际检查和前后对照。复用已有浏览器/CDP、服务与数据合同，不另建测试专用业务API；无新证据不宣称加速，真实、受控及合成样本分别记证，不提交受限源资料或私人运维信息。

## Acceptance criteria

- [ ] 先确认多年样本、查询类型与瓶颈，不从单日地图性能推断多年收益；缺样本或单次不足即标未验证/延后。
- [ ] 消费#37语义与真实日期/坐标证据，冻结有限合法样本和格式/实现版本；不将全历史转换作为实验或A分析前置。
- [ ] 至少比较同地点时间窗和同日期空间窗两类请求，原路径对两种候选分块布局；每次只变可解释因素。
- [ ] 记录打开次数、读取字节、耗时、峰值内存、压缩/元数据与磁盘，包含转换、更新及重复读取成本。
- [ ] 核对源值、时间、有效掩码和结果支持；分块不能悄悄改变分析粒度/空间范围，受限数据不整体传浏览器。
- [ ] 交付按负载的采用/延后/放弃及容量影响，不把某一种查询变快推广成全部场景收益。
