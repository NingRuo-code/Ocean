## What to build

重复合法窗口请求可复用正确服务产物，缓存按全局字节和版本受控，清理只作用于明确可再生的目标数据。

任务类别：近期。每项均交付一条可运行、可观察的完整用户流程或端到端测量/决策链，并包含自己的正确性参照、实际检查和前后对照。复用已有浏览器/CDP、服务与数据合同，不另建测试专用业务API；无新证据不宣称加速，真实、受控及合成样本分别记证，不提交受限源资料或私人运维信息。

## Acceptance criteria

- [ ] 复用已有窗口、版本缓存和维护能力，盘点实际使用路径后补全局字节、版本及并发预算，不重复从零引入缓存或压缩。
- [ ] 必要数据身份包含来源/处理、日期、层、窗口/尺度；图像增加映射版本，普通样式变化不无谓重算数值，不复用旧资格。
- [ ] 热点/重复窗口有命中证据，超预算、旧版本和失败残留按明确范围清理；仅文件数上限不能作为整体有界证明。
- [ ] 不预生成所有任意bbox组合，不通过缓存扩张掩盖慢扫描；原档、分析真源、受保护案例及报告与可再生缓存分开。
- [ ] 测试隔离命名空间内验证命中/失效/版本变化、字节上限、清理目标边界和重新生成；不清空生产缓存造冷启动。
- [ ] 同负载记录服务读算、传输、缓存字节/增长与峰值资源，说明收益/成本；无真实服务权限时只报告受控环境结果，不宣称现服达标。
