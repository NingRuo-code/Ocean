## What to build

项目负责人得到首轮地图优化后的同负载表现、资源上限与容量建议，能判断保留现服、限并发或针对性扩容，知道哪些规模尚未验证。

任务类别：近期。每项均交付一条可运行、可观察的完整用户流程或端到端测量/决策链，并包含自己的正确性参照、实际检查和前后对照。复用已有浏览器/CDP、服务与数据合同，不另建测试专用业务API；无新证据不宣称加速，真实、受控及合成样本分别记证，不提交受限源资料或私人运维信息。

## Acceptance criteria

- [ ] 综合首轮实际采用方案，按冻结设备/网络/资料和冷热场景复跑，报告3/1/2秒目标适用条件、实测分布和失败；未冻结或未测不能记达标。
- [ ] 据已取得盘点和峰值测量分开核算演示、东海多年及冷归档场景；含原档/热数据/派生/缓存/暂存/成果/备份与增长余量。
- [ ] 内存包含worker常驻、系统/文件缓存预留与允许重任务增量峰值；进程数、重任务并发和使用人数不简单等同，压缩字节不当RSS。
- [ ] 受控环境从单任务和低并发测本人后台任务与少量轻读混合负载，写停止条件；不在公开生产压测，不自动采购或迁移。
- [ ] 给保留现服、减少重复/限并发、冷热分层、增磁盘/带宽/CPU-RAM的证据化对照；未知配置/规模保持未知，不以旧估算当必需最低购买规格。
- [ ] 本项为首轮决策，不等待条件实验全部运行；候选后续采用须附同协议资源增量与更新报告。准备归档和任务中心仍由原模块负责，容量只提供预算及限制。
- [ ] 交付采用/限定采用/延后/放弃和残余瓶颈，区分本地、测试、现服和部署证据；首轮完成不关闭父级#17或宣称多年/月分析全部完成。
