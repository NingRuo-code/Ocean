## What to build

针对剩余主成本选择一种Worker、Canvas或WebGL方案，用完整地图操作做小样对照，确定是否值得有限替换。

任务类别：条件性。本项为条件性实验：先核对进入条件，成立才执行限定小样对照；不成立则交付有据的延后/不采用决定。决策完成不等于候选技术已实现或整项性能工作已完成。\n\n进入条件：完成局部重绘改进后，浏览器仍有显著绘制或主线程计算瓶颈。\n\n每项均交付一条可运行、可观察的完整用户流程或端到端测量/决策链，并包含自己的正确性参照、实际检查和前后对照。复用已有浏览器/CDP、服务与数据合同，不另建测试专用业务API；无新证据不宣称加速，真实、受控及合成样本分别记证，不提交受限源资料或私人运维信息。

## Acceptance criteria

- [ ] 先根据局部更新后的测量确定剩余主成本，冻结一个最适配候选；没有瓶颈则延后，不要求一次试遍或全图迁移。
- [ ] 保持同支持、对象/格、图例、色标和查询语义，建立可切回的限定原型，不把减少必需数据量当提速。
- [ ] 真实浏览器贯通加载、拖缩、选中、查点、键盘/触控及小屏；Worker路径同时计传输/序列化，GPU路径使用可比硬件及真实渲染模式。
- [ ] 比较用户完成时间、帧/长任务、初始化、可得进程/图像资源与维护代价，不以禁用GPU的功能测试推实际GPU收益。
- [ ] 数值、几何、缺测和版本身份正确先通过，关键操作不退化；仅局部采用时清楚标范围，原框架保留。
- [ ] 交付采用/限定采用/延后/放弃、回退及容量增量，无正收益也记录；不因此新增平滑模式、科学算法或在线模型。
