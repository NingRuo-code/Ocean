# Ocean 服务器容量与数据规模证据（2026-10-23）

## 结论与适用条件

当前不能证明已部署机器需要更换，也不能证明旧配置足以承载完整资料。本次没有取得现服 CPU、内存、磁盘、IOPS、带宽或服务进程清单，没有生产压测。先核对部署版本与实际数据目录，再用指定查询场景评估容量；本地已有 `/api/viewport`，但本日公开接口抽样返回 404，不能把本地实现的资源模型直接当线上实测。

**容量规划建议（工程估算，非购买或性能承诺）：**

| 使用范围 | 可评估的计算配置 | 存储规划起点 | 成立条件 |
| --- | --- | --- | --- |
| 当前 62 天东海演示、少量访问、热点缓存 | 现服先盘点；新建测试基准可从 4 vCPU / 8 GiB 评估 | 50–100 GB SSD 的小型服务盘，按实际 raw 清单调整 | 只服务区域窗口，重计算串行/限并发，批量生产另行运行；这些容量不是当前数据已经占用的尺寸 |
| 东海多年统计、历史查询、研究作业 | 4 vCPU / 16 GiB 优先评估 | 100–200 GB SSD 起步，AIS 和缓存另加实测预算 | 区域预裁剪、日期/空间索引、常用统计预计算；不在每次交互扫描全球多年原档 |
| 服务与多项离线研究同机，或数个重任务并行 | 8 vCPU / 32 GiB 优先评估 | 200–500 GB 热数据 SSD，冷归档分层 | 隔离在线与批任务，限制重任务并发；32 GiB 也不等于可把全球多年数组整体载入内存 |
| 全球完整归档与持续分析 | 在线服务仍可单独评估 4/16 或 8/32；归档/批处理另规划 | 约 TB 级数据池；保留稠密全量及中间副本时按 2–4 TB 或更大测算 | 选定 SST 产品、字段、年份、压缩与副本策略后计算；不包含未知规模 AIS 原始轨迹 |

vCPU 数量不能直接换算可同时使用人数；相同 CPU 核数的不同规格也未必等速。前三行存储是给系统、应用、暂存、缓存和增长留空间的规划值，不是从几 MB 静态文件直接推导出的必需容量。不运行真实 LLM；以后若本机部署模型，内存/GPU须另预算。

## 2. 三种“完整数据”必须分别估算

### 2.1 当前演示与东海多年

东海展示窗口 120–128°E、27–34°N，0.05° 网格约 `160 × 140 = 22,400` 格，按格心与实际边界核对最终形状。float32 SST 加 byte mask 的数组量是 `22,400 × 5 = 112,000 B/日`；62 天约 6.94 MB，仅元素，不含文件头、坐标、压缩、索引和对象。该格式来自当前 [SST 抓取器](../../backend/scripts/fetch_sst_samples.py)默认变量与 [NOAA 元数据](https://coastwatch.noaa.gov/erddap/info/noaacwBLENDEDCsstDaily/index.html)。

同一窗口若存 43 年锋面 int8 元素，约 0.352 GB；2002-09-01 至 2024-12-31 名义逐日 SST+mask 共 8,158 日，约 0.914 GB；两者合计约 1.266 GB 的未压缩元素模型。实际日期完整性、编码、NetCDF封装和派生数据须实测。**这不包含 AIS、强度、多尺度缓存或备份。**若保留全球锋面原档只在读取时裁剪，磁盘不会获得区域面积缩减。

AIS 目前只有一日公开 JSON 的直接样本。简单按它线性外推 62 日约 13.44 MB、名义 8 年 2,922 日约 0.634 GB，只能作“每天与该样本同大小”的情景，不能当实际历史数据量；格点密度、覆盖、船舶字段、原轨迹与压缩都会改变结果。应取得 `按年文件数 + 字节 + 格点数 + 日期覆盖` 的脱敏清单。

### 2.2 全球锋面归档

[Zenodo 数据发布页](https://zenodo.org/records/20356239)当前列出：1982–2024 年、15,706 个逐日文件、单日 7200×3600 格；`front_location.zip` 约 **19.7 GB**，位置及各年强度下载合计约 **116.8 GB**。GB 为页面的十进制展示，不能直接与旧笔记 GiB 比较；ZIP大小也不是解包或运行内存。强度仍在首轮范围之外。

[抓取脚本](../../backend/scripts/fetch_zenodo_front_samples.py)和原始出数注释记录全球锋面单日 NetCDF 约 1.27–1.3 MB；这是历史开发记录，不是本日抽取实测。以 1.27 MB×15,706 约 19.95 GB，只可作成员文件量级估计，不能据此假定解包倍数或逐年大小。应读取 ZIP 中央目录成员大小并抽几日验证，不必为盘点下载全档。

若把所有位置像元强行展开为 int8 稠密数组：`25,920,000 × 15,706 × 1 = 407.10 GB`；int16 为 814.20 GB。这是**指定内存/非压缩表示的容量**，不是宣称 ZIP 解包必定占 407 GB，亦不是压缩磁盘空间下界。

### 2.3 全球 SST 与“1982–2024 配对”

当前 SST 是 NOAA Geo-polar Blended，元数据起点 **2002-09-01**、0.05°、analysed_sst 为 float、mask 为 byte；它不能自动提供 1982 年起的同源温度。锋面发布使用的 ESA CCI/C3S SST 与项目演示 NOAA 产品不同。若要求 1982–2024 联合归档，应另选并核对匹配 SST 产品、版本、许可和目录大小，不能把目前两者拼成 43 年已齐资料。[NOAA 元数据](https://coastwatch.noaa.gov/erddap/info/noaacwBLENDEDCsstDaily/index.html)、[锋面来源说明](https://zenodo.org/records/20356239)

全球单日 25,920,000 格：float32 SST 元素 103.68 MB；加 byte mask 共 129.60 MB。以名义 8,158 日计，约 **845.82 GB / 1,057.28 GB**；这是假定稠密、未压缩的元素量，不是 NetCDF 文件下载量或已证实每个日期可用。若换成 43 年 float32 SST，单变量模型约 1.628 TB，来源和实际编码仍待确认。

旧 [全球 SST 脚本](../../tools/pipeline/sst_global_pipeline.py)写“约26MB/日、15,706天≈400GB”，混合了未核实文件尺寸和不属于当前 NOAA 产品的43年日期数，**不作为全量采购依据**。该脚本的 1°/0.25° 概览是显示资料，不足以替代 0.05° 分析输入；stride=4 从0.05°得到0.2°，目录文字0p25也须回查真实坐标。

## 3. 内存、IO与并发模型

[NumPy 官方](https://numpy.org/doc/stable/reference/generated/numpy.ndarray.nbytes.html)规定元素内存为形状乘 itemsize，不包含对象等额外开销。[xarray 官方](https://docs.xarray.dev/en/stable/generated/xarray.open_dataset.html)说明默认惰性索引，但访问时会载入 NumPy，可先裁剪降低内存；因此压缩文件小不等于计算内存小。相关本地 `sel → load/values` 路径见前述 data_access 和 exporter。

- 全球单日：int16 锋面约 49.44 MiB；float64 SST 约 197.75 MiB；再加 mask、连通域标签、比较布尔阵列、梯度临时阵列、Python 几何对象、JSON，峰值会大于二者相加。原始出数先读取后 coarsen，因此输出小不保证读取峰值也小。
- 仅把 31 天全球 float64 SST 同时物化就约 5.99 GiB，未含其余处理；不能用两个 worker 205 MB 的历史常驻注释预算这种任务。
- 东海小窗口的数值数组约为全球的 `22,400/25,920,000 ≈ 0.0864%`；实际IO不一定按比例缩小，取决于 NetCDF/HDF5 分块和压缩。应测读取字节、耗时与峰值 RSS，不只看输出像元数。
- [FastAPI 官方](https://fastapi.tiangolo.com/deployment/concepts/)说明多 worker 通常各自占用内存。规划可用 `RAM ≥ 系统/文件缓存预留 + W×常驻RSS + C×单重任务增量峰值 + 批任务峰值`；W是worker数，C是实际允许的重任务并发数，两者不等同。先限制全球/多年任务并发1，再在测试环境逐步验证。
- 存储规划公式：`磁盘 ≥ (原始保留量 + 派生量 + 缓存上限 + 下载/重算暂存 + 本机副本)/0.7`；0.7为本次建议的70%目标占用，并非软件要求。备份不应只放在同一盘。
- 例：全球位置 int8稠密模型407.10GB + NOAA SST+mask模型1,057.28GB，元素合计约1.464TB；若工作区保留一份同等大小中间副本并留30%余量，约4.184TB。实际压缩可少得多，更多变量、强度、AIS、多尺度输出可更大。这解释了“2–4TB或以上”的条件，不能称为已测最低购买量。

## 4. 带宽下界与缓存预算

理论无协议开销传输时间 `T秒 = 字节×8 / 带宽bps`，实际还受源站、丢包、TLS、CPU、磁盘及共享链路限制；下列是理想下界，不能作为到账速度或响应承诺。

| 载荷 | 10 Mbps | 100 Mbps |
| --- | ---: | ---: |
| 已发布锋面位置ZIP约19.7GB | 4.38小时 | 26.3分钟 |
| 锋面全记录下载约116.8GB | 25.96小时 | 2.60小时 |
| 1.057TB SST+mask未压缩元素情景 | 约9.79天 | 约23.5小时 |
| 本日216,834B活动JSON一次 | 0.173秒 | 0.017秒 |

下载归档通常看实例入站/源站实际吞吐，浏览器服务通常看公网出站；不能把购买的出站规格直接当归档下载速度。例：10位用户各2秒请求一次216,834B，平均纯载荷约8.67Mbps，尚未算其余图层；请求重复可由浏览器/代理缓存降低。此为设定流量情景，不是用户规模实测。

缓存需要按“日期数×常用窗口数×层/分辨率数×平均响应大小×有效版本数”估算，而非提前生成所有任意 bbox。优先预热热点、限制全局字节数与过期版本、测命中率。全球完整数据不应一次传到浏览器，继续采用概览与局部明细，统计按完整分析资料进行。

## 5. 升级前应补的最小证据

1. 运行现成 inventory 脚本取得脱敏摘要：CPU核数、RAM、swap、磁盘总/可用、文件系统、服务worker数、部署commit；不把原始输出、地址、账号及密钥路径提交仓库。
2. 用 [数据清单模块](../../backend/app/data_inventory.py)或等价只读统计核对 raw/processed/cache/outputs 的类型、日期、字节、配对日期及覆盖；额外计入 sst_global、AIS与重复备份，不能只统计manifest已有三类。
3. 对固定区域、日期、窗口和版本，分开记录读盘、数值计算、序列化、传输、浏览器解析、绘制；采冷/热对照、单请求及受控测试并发，记录 p50/p95、峰值RSS、CPU、IO和缓存增长。生产只做低频只读健康/功能探针。
4. 先解决线上/本地接口版本差异；若慢在网络、前端重绘或全历史无索引扫描，单纯加CPU/RAM不能替代路径修正。
5. 明确“完整”选哪一层：62天演示、东海多年、全球位置、全球位置+强度，还是全球+SST+AIS。第一轮建议区域多年研究与按需服务，全球冷归档独立，不把原始全量塞进应用盘。

本报告仅新增研究材料；未修改应用、任务规划或部署，未购买机器、安装依赖、下载大档或执行生产压测。
