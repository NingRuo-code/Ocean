# #67 GFW v3 四天原档的缺行与显式零

输入为 [Zenodo 14982712](https://zenodo.org/records/14982712) 的 `fleet-daily-100-v3` 四个八月原档。固定成员检查通过大小及 CRC32。该产品的 [README](https://zenodo.org/records/14982712/preview/README-fleet-v3.txt?include_deleted=0) 定义坐标是 0.01° 单元的左下角，并按旗国与渔法分组。这里只检查文件能说明什么，不计算锋面关系、密度或有效面积。

诊断窗口为 `123.65 ≤ cell_ll_lon < 124.35`、`29.70 ≤ cell_ll_lat < 30.30`，按规则网格有 4,200 个候选位置。窗口包住原登记点附近区域，用于比较文件行是否出现；它不代表研究半径或海域掩码。每格优先记“任一组捕捞小时正值”；无正值且至少一组有在场时长才记“显式零，有在场”；其余有行但两种时长均为零单列。缺行是剩余格位数，不赋值。末列是正值格中还含零捕捞且有在场组的子集。

复核使用标准库 CSV 和十进制坐标先按格及组去重，另以 pandas 按坐标分组独立对照，同一日期的各项计数完全一致。所选窗口内未发现重复同日同格同旗国同渔法组；四文件各自仅有与成员名一致的 `date`。文件内部一致性不能证明日界是 UTC，也不能证明缺行是零。混合格表明显式零首先属于发布组。零、正值、缺行及在场都不能代替固定版逐日接收质量证据。

核验输出仅为聚合计数，原 CSV 和逐格内容不进入 Git。该检查不改变真实分析准入，也不据此选择新的研究中心或阈值。
