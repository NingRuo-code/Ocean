# Ocean 海温配色与色块显示核查

日期：2026-10-23。范围：本地阶段分支源码只读核查；仅新增本笔记。未改应用、未测性能、未核对线上画面。Q41 已选择固定绝对温标；具体上下限与最终视觉实样仍需按数据和设计评审落实。NCL 官方色表及 cmocean 资料由主任务核对；本文不声称已选定或接入新色表。

## 1. 结论与事实

“颜色生硬”和“空间块状”是不同问题，换色表只能直接处理前者，不能恢复分箱或降采样丢掉的细节。当前可确认存在以下来源：

| 层次 | 已核实的本地行为 | 作用与边界 |
| --- | --- | --- |
| 温度量化 | `backend/scripts/export_prototype_data.py:49` 定义 `SST_BIN_C = 0.5`；`:377–413` 将温度除以 bin_c 四舍五入并写为 RLE | 相近温度落入同一档，同色区域会连成片；已经量化的 payload 不能通过换色表还原原始小数 |
| 视野适配再次分箱 | `frontend/prototype/prototype-data.js:402–425` 的 `sstFromViewport` 独立写死 `binC = 0.5`，按 `Math.round(value / binC)` 重建网格游程 | 即使将来接口返回更细温度，适配器仍会量化；只改导出常量不足以统一路径 |
| 空间抽样/LOD | `prototype-data.js:254–262` 按视野给 step 1/4/20/40；`backend/app/viewport.py:346–384` 对 SST 的行列按 sample_step 间隔抽样；适配器 `:447–455` 以 baseRes×step 建显示网格 | 远景会出现更大的显示单元；抽样并非等价于面积平均，不应把粗格显示误称精细观测或完整空间聚合 |
| RLE 与路径合并 | `export_prototype_data.py:303–316`、`prototype-data.js:369–382`、`prototype-fishing.js:367–392` 合并同档相邻格；`:557–568` 按档号生成填色路径，设 `shape-rendering: crispEdges` | RLE 本身是对分箱后网格的压缩，不能笼统归咎“压缩导致错误块”；显式硬边会强化网格边界观感。改变抗锯齿仅改变边缘显示，不增加数据精度 |
| 色表与不透明度 | `prototype-fishing.js:529–545` 使用固定 16–33℃ 控制点，在相邻颜色间插值并截断两端；`:564–568` 概览/明细透明度不同 | 这是颜色插值，不是温度空间插值。底图、粗细片和选择态透明度会影响最终屏幕颜色，须用真实叠加场景评审 |
| 图例未同源 | `frontend/prototype/prototype-fishing.html:141` 单独写渐变，与 JS 16–33℃控制点并非同一份配置；`:448` 仅标水温产品名 | 只换 HTML 渐变或只换绘图色表都会留下不一致；需要共享色表、域、单位、越界及缺测规则 |

补充路径边界：`backend/app/frontend_payload.py:197–214` 的 `_thin_window` 对过大 SST 窗口隔格取样，像元上限见 `:165–169`；`:357–395` 分别输出局部 SST 与全球粗 SST。`:118–162` 的 `coarsen` 是锋面分类概览规则，不可说成 SST 块平均。主地图 `prototype-data.js:331–334` 目前请求 `/viewport`，不能将 raw `/frontend/day` 路径所有行为混为主地图当前行为。

## 2. 后端 PNG 路径也要纳入固定温标契约

`backend/app/raster_render.py:12–39` 有另一套 `_SST_STOPS`，`sst_scale` 按每个窗口的 2%/98% 分位和至少 4℃跨度动态拉伸；`:93–119` 对原数组逐格配 RGBA，并未生成更细温度网格。

`backend/app/main.py:613–643` 的 SST/combined raster 显式调用该动态 `sst_scale`，并将范围写入 `.scale` 缓存和 `X-Raster-Scale`。这是与 Q41 固定温标要求需要统一的另一条实现。当前 `prototype-fishing.js` / `prototype-data.js` 未检索到调用该 SST raster 接口，不能断言它就是主地图所见色块的成因；也不能只修 SVG 而让报告/其他消费端继续悄悄使用不同温标。

## 3. 候选处理与禁止越界

- 按已核对官方资料建立变量语义：绝对 SST 用顺序色表候选 thermal；温差/异常用以有意义参考值为中心的发散色表候选 balance。它们是候选，不能未经实际图样评审直接记为已选定。
- 固定温标是固定“温度→颜色”的关系，不要求抹除真实网格。具体范围须覆盖研究季节/海域并明示低于/高于范围的颜色与端点；不能悄悄按每个窗口重新拉伸。
- 候选减块步骤：先比较新色表与现有分箱，再评估在原始资料允许时保留更细显示值、调整合理 LOD 与抗锯齿。更细分箱会增加游程/体积，应与性能任务一起测量，不能预设一定更快。
- 不用跨缺测/陆地的模糊或插值冒充观测；不从 0.5℃档位虚构更细温度，不从粗概览虚构空间精度。若以后采用仅展示用重采样，须标方法、保留真实格点查询与分析真源，独立评审。
- 缺测、无锋面及活动零值分别表达；海温配色调整不能同时偷偷改变锋面阈值、活动门槛或统计输入。

## 4. 建议补入 U2 的验收项

1. **建立同源映射契约。** SVG、实际使用的 PNG/导出图与图例使用同一色表版本、固定温度域、单位、越界和缺测规则；缓存身份包含渲染映射版本，旧 PNG 与 `.scale` 不得串用。
2. **跨日期/海域颜色可比。** 用相同温度的已知格点检查换日期、缩放和范围后色表映射不变；透明叠加的视觉差异另行核对，不把合成屏幕像素当纯色表值。
3. **分别评审颜色与空间块。** 同日期/同窗口固定范围对照旧图、新色表图与必要的细粒度显示候选；注明原始网格、显示网格、bin_c、LOD，不把“渐变更顺”验收为“空间精度提高”。
4. **保留缺测与叠加辨识。** 至少覆盖夏/冬或冷/暖场景、小/中/大视野，SST 单层、叠锋面、叠活动及缺测边缘；图例刻度、低高端、选中态与底图上可读。
5. **数值与性能共同回归。** 比较图前后格点读数、最近锋面几何和分析总量；显示值若从分箱改为更细值，应记录可解释的编码差异及来源，不改变原始科学计算。记录 payload/游程数、绘制耗时和内存，不靠删除有效资料消块。
6. **状态分开记录。** 官方资料已核对、视觉候选、用户选样、实现完成、本地验证、合并与部署分别留证。本轮主任务已将“色块来源、显示粒度与跨路径固定温标”补入 U2.1a–d；实际接入与修复仍未实施，不能将规划补齐算作界面已完成。
