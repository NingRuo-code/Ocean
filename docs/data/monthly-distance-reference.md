# 受控月分析：直接距离参照（#62）

沿用[原受控月分析入口](controlled-month-analysis.md)。本地维护者配置 `OCEAN_MONTHLY_DISTANCE_INPUT_PATH` 指向已登记的小型自有合成输入，及既有本人执行凭据。新用途 `monthly_distance_reference` 通过 `POST /api/query/monthly-analysis` 显式运行；原结果入口仍按运行身份读冻结结果，这一用途的执行和读取都需本人凭据。关闭配置时不可用。仅限单进程单任务同步运行，失败不保存部分结果，无自动扫描、缓存、队列、生产部署或研究放行。

请求沿用原点、月、半径与版本字段。`input_version` 为完整登记输入字节的 `sha256:<hex>`；`method_version=wgs84-distance-bands/v1`，`parameter_version=half-open-bands/v1`。从仓库运行的服务执行对应的本地确定性工具。输入合同 `ocean-month-distance-input/v1` 包含：

- `conditions`：#41 的 `A_month` 条件，恰好一个圆，与请求点/月/半径一致，复用必需层、来源ID、分摊、质量和方法版本；
- `regional_cells`：#39 的 `ocean-regional-cells/v1` 输入，目前只登记 `evidence_kind=synthetic` 作为软件参照；不将地图限点、月图、旧事件表转为观测；
- `front_days`：同日、同版本的线材料，元素为 `date`、`source_id`、`lines`（WGS84坐标序列）。条目缺失与有条目但`lines=[]`分开；
- `distance_edges_km`：维护者为该参照预先固定、严格递增的距离端点（1–6个，均在0–100公里）；`front_position_error_km`是该线材料的位置误差（本次为明确的夹具假设，不代表真实产品精度）。完整输入哈希覆盖这些条件，不根据活动值选带。

原P0引擎确定同日共同支持及边界分摊。每个有贡献的活动单元取其共同支持部分的代表点，与同日已检出锋线匹配。WGS84线上样点的间隔不超过50米；最近样点给距离上界，沿线半步与来源位置误差给保守距离区间。距离定义适用于代表点，不能据此还原格内船位。按 `[lower,upper)` 互斥分组，区间穿过带端点、线材料缺失或最近搜索支持不足归未知；最外组只在能证明有限下界时给出。搜索通过验证锋面有效支持对所需范围的覆盖，不以分析圆裁断；无已检出线也不推断无限远。已知零活动与没有分母分开。

逐日各组保留同一共同支持上的小时与面积时间，核对分组加总守恒。活动已观测但未分配到共同支持的部分，在日/月分别单列小时和面积时间及原因；这部分不进入密度。月密度为小时之和除面积时间之和，不取日密度的简单平均；未知距离组也单列分子、分母，缺日不补零。外搜索超出P0支持边界时仍保留能核实的内圈下界。结果记录P0共同支持、条件、方法、运行库及输入身份，无源细格和个人路径。

本阶段为直接距离软件参照，首选月正式计算须经[#64的P0执行准入](monthly-execution-qualification.md)、相应来源/粒度/许可和#68真实复算。东海2024-08真实锋线时间、有效支持与完整日历仍未通过，结果不能解释为实际捕捞活动分布。
