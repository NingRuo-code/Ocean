# 第 1 周输入文件需求清单

## 目的

本清单只服务于第 1 周的“数据理解与原型确定”。文件齐备并完成检查后，才能进入第 2 周的海温、锋面和冷暖侧图层开发。

当前进展：已从 Zenodo 按单日提取并读取 2024-08-05 至 08-07 三个真实锋面文件。锋面样例不再是阻塞项；当前仍缺同日期 SST、人工参考结果和样例海域确认。

## 一、必须提供的文件

### 1. 真实锋面位置 NetCDF

最低要求：

- 格式：`.nc` 或 `.nc4`；
- 数量：至少 1 天，建议连续 3—7 天；
- 日期：文件名或文件内部必须能够确定观测日期；
- 变量：必须包含 `front` 或含义相同的锋面位置变量；
- 坐标：必须能获得每个像元对应的经度和纬度；
- 数据必须来自实际数据集，不能使用手工模拟值；
- 允许提供 ZIP，但压缩包内必须是可单独读取的逐日 NetCDF；
- 不需要下载约 18.31 GiB 的完整 `front_location.zip`。

文件中至少需要确认：

- 纬度变量名，例如 `lat` 或 `latitude`；
- 经度变量名，例如 `lon` 或 `longitude`；
- `front` 的维度顺序；
- `front` 的数据类型；
- `_FillValue` 或缺失值；
- 经度范围采用 `[-180, 180]` 还是 `[0, 360]`；
- 纬度是递增还是递减；
- `-10、10、30、0、-128` 是否与 Zenodo 说明一致。

建议文件名：

```text
front_YYYYMMDD.nc
```

建议放置位置：

```text
data/raw/front/YYYY/front_YYYYMMDD.nc
```

### 2. 同日期海表温度 SST NetCDF

Zenodo 的锋面数据不能代替海温数据。为了满足原指导书要求，必须另行提供与锋面样例匹配的 SST。

最低要求：

- 格式：优先 `.nc` 或 `.nc4`；
- 日期：与锋面样例至少有 1 个完全相同的日期；
- 范围：覆盖选定的样例海域；
- 坐标：包含经纬度坐标或明确的栅格定位信息；
- 变量：包含 SST 数值；
- 单位：必须明确是 `°C` 还是 `K`；
- 缺失值：必须明确；
- 分辨率：最好与锋面数据一致；如果不一致，必须提供重采样或配准说明；
- 时间定义：明确是日平均、瞬时值还是其他时间产品。

建议文件名：

```text
sst_YYYYMMDD.nc
```

建议放置位置：

```text
data/raw/sst/YYYY/sst_YYYYMMDD.nc
```

### 3. 数据字段说明

格式可以是 Markdown、Word、PDF、TXT 或表格，但至少需要说明：

- 每个变量的名称和业务含义；
- 维度、形状和维度顺序；
- 经纬度范围和分辨率；
- 数值单位；
- 缺失值和陆地值；
- 时间和时区定义；
- 冷暖侧编码规则；
- 锋面线编码规则；
- SST 来源及产品名称；
- 数据版本和引用方式。

如果没有现成说明文件，可以由我们运行检查脚本后生成初稿，再请海洋领域老师确认。

### 4. 一份人工确认正确的参考结果

至少提供以下一种：

- 某一天、某海域的正确可视化图片；
- 论文中的明确图号及其对应日期和范围；
- 现有 MATLAB/Python 程序生成的结果图；
- 海洋领域老师确认过的截图。

参考结果必须能回答：

- 海温颜色分布是否正确；
- 锋面是否叠加在正确位置；
- 冷侧和暖侧是否画反；
- 海岸线、经纬度是否对齐。

没有这份参照，只能证明“程序能画图”，不能证明“科学含义正确”。

## 二、强烈建议提供的文件

### 5. 现有数据读取或绘图代码

可接受：

- `.py` Python 脚本；
- `.m` MATLAB 脚本；
- Jupyter Notebook；
- 论文补充材料中的代码；
- 仅包含关键读取和绘图步骤的代码片段。

主要用于确认坐标转置、冷暖侧掩码、强度恢复和颜色方案，不要求直接集成到系统。

### 6. 数据目录或文件名规则说明

需要说明：

- 完整数据按年、月还是日组织；
- 日期如何从文件名解析；
- 锋面和 SST 如何配对；
- 闰年和缺失日期如何处理；
- 是否存在多个分辨率版本。

### 7. 数据校验信息

对于下载文件，最好同时提供：

- 来源链接；
- 下载日期；
- 文件大小；
- MD5 或 SHA-256；
- 数据版本。

这可以避免下载不完整或成员之间使用不同版本。

## 三、需要老师或合作方明确回答的问题

1. 第一版选用哪个典型海域？建议给出经纬度边界，而不只给海域名称。
2. 第一版选用哪几个连续日期？
3. 第一版使用哪个分辨率？
4. SST 数据具体来自哪个产品、在哪里下载？
5. SST 与 `front` 是否使用同一网格？
6. Zenodo 数据是否包含可单独下载的逐日预览文件？
7. 数据中是否存在“锋面编号”？当前 Zenodo 说明只确认了栅格变量 `front`。
8. 如果没有锋面编号，第一阶段的信息卡是否允许只展示锋面存在性、冷暖侧和栅格属性？
9. 冷暖侧应显示整个锋区，还是只显示锋面线附近的方向标记？
10. 哪一张现有结果图可以作为第一阶段数据正确性的验收基准？

## 四、当前暂时不需要的文件

- 1982—2024 年全量数据；
- 全部 43 个逐年锋面强度压缩包；
- 大规模历史统计结果；
- 预测模型和预测结果；
- 大语言模型或向量知识库；
- 用户数据、账号和权限配置；
- 锋面追踪与分裂合并标注。

提前获取这些文件会增加下载和整理成本，但不能解决当前第 1 周的阻塞问题。

## 五、推荐的最小交付包

最理想的第 1 周输入包如下：

```text
ocean_sample/
├─ README.md
├─ front/
│  ├─ front_YYYYMMDD.nc
│  ├─ front_YYYYMMDD.nc
│  └─ front_YYYYMMDD.nc
├─ sst/
│  ├─ sst_YYYYMMDD.nc
│  ├─ sst_YYYYMMDD.nc
│  └─ sst_YYYYMMDD.nc
├─ reference/
│  └─ expected_YYYYMMDD.png
└─ code/
   └─ read_and_plot.py 或 read_and_plot.m
```

其中锋面和 SST 文件应使用相同的连续日期，`README.md` 应给出样例海域边界、日期、变量、单位和来源。

## 六、收到文件后的处理顺序

1. 记录文件来源、大小和校验值；
2. 使用 `backend/scripts/inspect_netcdf.py` 检查每个 NetCDF；
3. 生成变量和坐标检查报告；
4. 确认锋面值编码及 SST 单位；
5. 裁剪约定海域并生成独立检查图；
6. 与人工参考结果对照；
7. 更新最终数据字典；
8. 完成第 1 周验收记录；
9. 验收通过后进入第 2 周图层开发。
