# Ocean W 分析工作台实施规格

整理日期：2026-10-24。关联既有 W #21、执行总纲 #13，承接界面规格 #24 与 A #60、B #72、C #85。状态：已发布 [规格 #95](https://github.com/NingRuo-code/Ocean/issues/95)，标签 `ready-for-agent`；验证边界已获用户确认。实施任务已按确认发布。发布标题：`[Spec] W 分析工作台：A/B/C 引导提交、任务状态与同源结果联动`。

实施任务已按用户确认发布为#96–#108：[任务与阻塞关系](../tickets/w-analysis-workbench/README.md)。本行仅为本地导航，远端规格正文保持不变。

## Problem Statement

使用者希望从地图选择时间、位置和公里范围，方便地了解附近活动与锋面关系，再按需要执行完整月空间关系、固定海域事件响应和区域证据比较。分别找到统计脚本、理解参数、等待计算并寻找报告，仍有很高使用门槛；只有快捷按钮或静态说明也不能完成这条使用流程。

现有工作台基础与首批界面规格解决入口、筛选和简洁展示，A/B/C分别定义确定性计算和证据合同。W需要把这些已验证能力接到真实可操作界面，让使用者知道能做什么、缺什么条件、是否确实提交、任务在做什么、哪个结果属于哪次条件，以及失败后如何继续。原有历史频次查询和实验性规则参考不能冒充新的A/B/C分析。

本模块服务渔业活动理解，首先帮助使用者读懂表观捕捞活动与锋面关系及其证据局限。地图保持主视图，结果简洁、细节按需展开；不把统计研究变成捕鱼保证、评分排名，也不以AI聊天作为使用这些功能的必要条件。

## Solution

沿用按钮呼出的非模态左侧工作台，将A“月度空间关系”、B“事件前后变化”、C“区域证据比较”做成引导任务入口。每项用简短问题说明用途，给出可用范围、当前已应用条件与必要补充；筛选仍是左侧呼出的独立浮层，快捷功能和AI区域保留各自位置。

查看已有结果与提交新分析是清楚的操作。只有本人在条件齐全、用途合格、服务支持且权限允许时，明确点击提交才接受耗时任务；不增加重复确认卡。任务与提交条件、版本和身份绑定，关闭面板后仍可浏览地图并重新找到任务。右侧保持当前/历史/预测的既定职责，历史中提供A/B/C的简短结果，完整图表、对照、兼容判定和证据放到底部按需展开。

A先接入，B/C分别在各自真实合同交接后开放，不等待完整AI或全部后续任务中心。复用现有确定性服务、资格、结果与状态合同；若上游只有离线计算入口，W的完整在线提交必须补齐或接入最小服务适配、持久任务记录和服务端执行权限，不能用前端模拟代替。完整公共任务中心的自动恢复、归档准备和长期管理仍按后续专项建设。

## User Stories

1. 作为使用者，我希望一键呼出或收起分析工作台，以便在地图和分析入口之间自然切换。
2. 作为使用者，我希望工作台展开时仍能拖动、缩放和选择地图位置，以便分析不阻断观察。
3. 作为使用者，我希望快捷分析和AI各自清晰可见，以便不用先理解AI就能完成分析。
4. 作为使用者，我希望筛选和图层通过独立浮层调整，以便它们不挤占快捷功能与AI模块。
5. 作为使用者，我希望用简短中文了解月度关系、事件变化和区域比较各能回答什么，以便选择合适任务。
6. 作为使用者，我希望分别看到各任务已可用、缺数据、待能力交接或无执行权限的状态，以便不误按虚假入口。
7. 作为使用者，我希望A可用后先使用A，以便不必等B/C全部完成。
8. 作为使用者，我希望看到任务实际支持的资料日期、地域和公里范围，以便选择可分析条件。
9. 作为使用者，我希望新任务从已应用的筛选条件起步，以便不重复填写位置和范围。
10. 作为使用者，我希望地图视窗中心、未应用的坐标草稿与分析点有明确区别，以便移动地图不会偷偷改变任务。
11. 作为使用者，我希望月分析明确显示完整年月，而日视图日期保持原含义，以便不会把几天资料误当整月结果。
12. 作为使用者，我希望事件分析明确显示固定区域、搜索期和前后窗口政策，以便了解实际问题而非追踪同一个日编号。
13. 作为使用者，我希望区域比较明确列出不同候选圆域、共同条件及A/B证据板，以便不会误把两种估计对象混在一起。
14. 作为使用者，我希望缺条件或条件冲突在提交前就能定位到具体项，以便直接修正。
15. 作为使用者，我希望缺数据、资格不足和源身份未知分别说明原因，以便知道应换条件还是等待准备。
16. 作为使用者，我希望能查看已有合法结果而不启动新计算，以便快速探索已完成证据。
17. 作为本人，我希望明确提交合格任务后直接得到受理状态，以便无需重复确认同一分析意图。
18. 作为本人，我希望双击、提交超时或重复发送同一意图不会生成不知情的重复任务，以便避免浪费资源。
19. 作为本人，我希望任务保存提交时的请求、输入支持和版本，以便之后改条件不改变其研究含义。
20. 作为本人，我希望看到真实排队、执行阶段、失败或完成状态，以便知道任务是否仍在运行。
21. 作为本人，我希望没有真实进度百分比时看到阶段说明，以便不被模拟进度误导。
22. 作为本人，我希望收起面板、切换视图或刷新网页后仍能查询已受理任务，以便不用持续保持页面打开。
23. 作为本人，我希望网络断开时明确知道状态暂不可核实，以便不会误认失败并重复提交。
24. 作为本人，我希望重新连接后按原任务身份查询，以便恢复状态而非偷偷重跑。
25. 作为本人，我希望失败任务保留条件与原因，并允许明确重试，以便能有依据地恢复工作。
26. 作为本人，我希望重试原条件与按新条件提交有区别，以便不会把源版本变化隐藏在同一任务里。
27. 作为本人，我希望取消有服务端真实结果，并区分取消请求、已取消和来不及取消，以便知道计算是否真正停止。
28. 作为本人，我希望取消或失败不会发布半成品，也不会删除此前有效成果，以便保留可信证据。
29. 作为使用者，我希望修改当前筛选后仍能看到旧结果的原条件和待更新提示，以便不把旧数字当新条件结论。
30. 作为使用者，我希望较慢的旧任务或旧请求完成时不会覆盖正在查看的新结果，以便快速操作后仍能信任界面。
31. 作为使用者，我希望主动打开旧任务时清楚看到它的日期和范围，以便回顾旧证据而不偷换全局筛选。
32. 作为使用者，我希望右侧只展示少量关键数字和简短分析，以便迅速理解结果而不被规则堆砌淹没。
33. 作为使用者，我希望从摘要一键展开同一结果的底部图表、表格和来源，以便深入核对时保持上下文。
34. 作为使用者，我希望A明确区分小时、面积时间密度、距离和侧别支持，以便看懂空间关系而非单看总量。
35. 作为使用者，我希望B明确区分前7日、当日、后1–3日、真实后1–7日及对照，以便不会把不完整窗口当完整响应。
36. 作为使用者，我希望C保留所有候选及逐项可比理由、部分失败和描述差值方向，以便不被默认排名误导。
37. 作为使用者，我希望未知、缺测、无事件和真实零值分别呈现，以便正确理解没有数字的原因。
38. 作为使用者，我希望地图中的位置、圆域和关联日期来自当前打开的结果，以便核对图和数字说的是同一件事。
39. 作为使用者，我希望结果定位属于明确操作且保留原地图框架，以便不会因打开分析被突然换日期、换范围或替换主图设计。
40. 作为使用者，我希望摘要、图、表和允许下载的聚合证据属于同一结果身份，以便复核时没有多套数值。
41. 作为使用者，我希望看到方法局限、样本和区间不具备时的原因，以便不把相关关系当因果或渔获预测。
42. 作为访客，我希望自由浏览允许公开且已就绪的地图与合法结果，以便了解系统能力而不用获得后台权限。
43. 作为本人，我希望个人任务和研究成果不会因演示公开而自动暴露，以便控制公开范围。
44. 作为本人，我希望执行、重试、取消和任务读取都由服务端校验权限，以便隐藏按钮不是唯一保护。
45. 作为使用者，我希望小屏、键盘操作和弹层关闭行为仍清楚可用，以便不被面板遮住地图或丢失焦点。
46. 作为项目负责人，我希望真实A/B/C浏览器流程与合成故障测试分开记录，以便判断功能、资料和研究证据分别完成到哪一步。
47. 作为项目负责人，我希望工作台不隐式下载归档、发起AI调用或额外研究，以便每次耗时操作都有明确意图和边界。
48. 作为后续模块维护者，我希望工作台复用任务和结果的公共合同，以便以后接入完整任务中心与AI时不用再造科学计算。

## Implementation Decisions

1. **归属与复用。** W归属既有#21及#13，UI基础沿用#24，月分析消费#60/#71，事件消费#72/#84，比较消费#85/#94。原历史频次、旧响应查询和实验性规则参考保持其准确名称与范围，不能直接换标签当A/B/C。实施前核对实际分支、部署与资料，Issue关闭不等于实际服务就绪；本规格不修改既有父级或科学协议。

2. **分批可用，不反向阻塞研究。** A入口可以独立交付，B和C分别等对应结果/受控执行合同；C月度与事件板分别开放已可用部分，完整C验收仍需两板。U1的工作台、统一筛选、请求隔离和底部阅读能力按实际使用成为相应前置，不将全部U1/U2、P1或完整TASK中心一揽子设为W前置。A/B/C计算和交接不得反向依赖W。

3. **界面分工保持已确认设计。** 左深色工作台内是快捷分析和紧凑AI两个模块；日期、坐标和公里范围属于独立筛选浮层，图层属于独立浮层。右浅色仍为当前/历史/预测，A/B/C在历史提供轻量摘要、由工作台定位到底部详细阅读，不新增常驻宽大统计栏、第四个AI标签或新顶栏。所有侧栏可收起，非模态，不阻止地图和键盘操作；沿用既定工业风格，不另做设计体系。

4. **条件模型。** 区分未应用筛选草稿、已应用地图条件、任务待提交请求、已受理任务快照、正在查看的结果。继承已应用条件是初始化操作，未提交的任务草稿可主动同步但不得悄悄改写已受理任务。A由所选日初始化所属年月，并明确显示整月；不自动凑日或替换月份。B保留搜索期、跨月上下文和窗口身份。C显式添加至少两个不同固定公里圆域，保留顺序、共同条件、证据板及兼容政策，不以日F编号作事件身份；原有日期/半径即时更新与坐标应用逻辑仍按#24执行。

5. **能力与资格轻量检查。** 用真实服务能力、P0用途资格与A/B/C结果可用状态决定入口。校验使用已登记审计和轻量读取，表明核实时间/身份；客户端提示不代替受理时服务端复核。公开/就绪范围、缺条件、资格不足、能力未实现、服务不可达、无权限是不同状态。归档存在不等于已准备；提供原因与后续准备入口的条件说明，不在打开面板或检查条件时下载、加工或重分析。

6. **最高层接缝。** 以一条浏览器任务流程消费既有确定性分析与结果合同，新增接缝限于必要的工作台服务适配：能力/支持与只读结果，显式受理及任务状态/操作。沿用现有API服务边界，不另建科学引擎、测试专用业务服务或第二套资格/缓存。若A/B/C交接只具备离线受控入口，实施必须把同一计算适配到真实受控服务；本地脚本成功不能证明在线可提交。

7. **在线执行所需最小公共基础。** W完整运行必须有服务端本人权限、明确的任务受理与身份、持久轻量任务记录、可查状态、原条件、失败原因、结果引用及真实取消/重试动作。优先消费已实现并可验证的公共设施；缺失时在W实施任务中明确最小增量及责任，或绑定届时已发布的具体公共任务，不以一个尚未拆分的“等待TASK”替代交付。只读结果接入可先完成并独立记证，不能因此勾选完整W执行验收。完整队列平台、自动续跑和保留策略不随此前置整包引入。

8. **显式提交与幂等。** 查看已有结果是只读；新分析、重算或C已登记支持衍生是明确提交，不能由页面打开、修改筛选、轮询状态、点击解释或刷新触发。本人点击合格提交即为意图，不再重复确认；受理前由服务端复核权限、实际支持/版本、范围和资源边界。不满足则拒绝并解释，不把预检成功当保证。一次提交意图有稳定幂等身份，重复发送返回原受理结果；提交响应丢失后先按该身份核实，不自动新建。明确重算是新的受理意图，与复用已有完成结果区别记录。

9. **条件、资料与任务/结果身份。** 请求使用规范化年月/搜索期、固定区域、半径、任务/板类型及已冻结主方案；受理记录绑定当时已知的源、支持、几何/方法/参数、对照与资格身份。若排队后实际源身份变化，按既有合同重新核实并中止旧请求或要求显式新请求，不静默换源。任务身份、提交意图身份和结果身份各司其职，不只用日期或坐标当缓存键；图表与摘要引用同一成功发布快照。敏感底表不进浏览器，受限资料和细网格不进入公开产物。

10. **真实生命周期。** 至少区分待提交、受理中/受理待核实、已受理或排队、执行、取消请求中、已取消、失败/中断、完成以及状态暂不可核实；允许采用既有合同等价状态，不强造后台不支持的阶段。完成必须指向原子发布且校验成功的结果；结果可能受限或部分可用，和执行失败分开解释。仅有轮询开始、日志生成或文件存在不等于成功。进度采用真实阶段/已完成工作量，未定义总量不展示百分比。

11. **最小持久性与恢复边界。** 已受理任务不能依赖页面继续打开；关闭、导航、刷新后通过服务端授权记录和有限的本地引用恢复查询。断网只表示状态未知，恢复后查询原任务，不新建分析。服务器发生中断后，W读取实际恢复/中断状态；无法验证存活的执行不能永远显示运行，也不能自动宣称失败后重试已成功。安全自动续跑、不重复步骤和完整重启恢复按Q49的公共TASK专项继续落实；W的持久记录与正确中断呈现不冒充Q49全部完成。

12. **重试、取消与竞争。** 重试须本人显式操作并新建可追溯尝试，注明与原任务关系；仅当前源身份仍可满足冻结合同才可称原条件重试，源变化则说明并按新请求受理，原记录保留。无需重跑时优先查看现有合法结果。取消由服务端接受并在安全阶段停止或拒绝，前端停止等待不算取消；完成与取消竞争由服务端权威终态解释，不丢有效完成结果。旧任务和取消任务迟到消息不得覆盖新选择。未具备取消能力时不得给假成功，必须作为尚欠实施能力记录，不能完成完整W验收。

13. **结果导航及条件改变。** 改日期/区域后，旧详情保留原条件与“条件已改变，待更新”提示，不自动重算、不将其放在新条件标题下。新任务结束可提示，但只有当前明确选中且身份匹配的结果可更新对应摘要/详情。用户主动选择旧任务会打开原快照，不自动覆盖全局地图筛选；“在地图定位此结果”是另一个明确操作，说明需要改变的日期/范围后沿既有应用逻辑更新。不增加多余确认流程；地图叠加/定位和结果分别标示自身身份，旧B相对日不能冒充地图实际日期。

14. **精简而可复核的阅读。** 右栏默认一个主要事实、少量补充和短解释，数据充足时直述结果，缺口时直述不足，不常驻评分规则或全部方法文字。底部图、表、证据来源、方法和已有聚合成果下载按需展开；不在本规格新造PDF报告平台。A保留H/E单位、距离/侧别和未知支持；B保留各真实窗口、对照、事件相关组与已有区间；C保留A/B分板、逐指标/区域对兼容性、不可比及缺失候选，差值仅使用其已验证结果，不拼区间做新检验。没有独立研究结果时不得提供置信度、推荐排名或成功概率。

## Testing Decisions

1. **主验收接缝已获用户确认。** 从真实浏览器中点击工作台、调整已应用条件、填写必要补充、显式提交，经实际受控服务到任务状态与正确结果，再到右侧简短摘要、底部同源图表/证据和明确地图定位。复用现有浏览器交互/布局检查与API测试能力，按可见行为断言；不只检查按钮存在、内部函数调用或静态截图。A先闭环，B/C按各自真实能力分别验收。

2. **少量独立API核对辅助同一流程。** 核对真实受理次数、幂等身份、冻结请求/源、权限、任务状态、发布结果和前端展示对应关系；用可手核聚合结果比对摘要/图/表/允许下载，不在W重测全部科学引擎。现有数据检查用于复用字段/单位/缺测核对，A/B/C的手算和真实复算证据继续沿各自验收引用。只读消费不得隐含执行、归档下载或AI调用。

3. **条件与异步竞争。** 覆盖未应用坐标、全局日与整月、B跨月窗口、C候选/分板；编辑后旧结果待更新、旧请求迟到、新任务与旧详情切换、源同路径变化、资格过期、预检后受理失败及当前版本未知。断言旧条件不能显示为新条件结论，地图移动不改变已受理请求。

4. **故障与操作。** 在受控环境注入双击/提交响应丢失、网络断开重连、刷新、面板关闭、任务失败、中断、取消与完成竞争、明确重试和不支持动作。分别证明不重复受理、不发布半成品、不误报取消、旧任务不覆盖新任务，关闭页面后可重新查原记录。浏览器取消等待不是任务取消；只有模拟状态只能证明前端分支，不能替代实际服务操作验收。

5. **服务端权限与资料边界。** 用本人/访客及失效授权验证提交、任务读取、取消、重试与逐源结果访问；访客继续可浏览公开且就绪范围。直接请求和猜测身份不能取得私有任务或发起重计算；C含一项私人来源时不泄露。检查错误/日志/导出没有凭据、私人路径、细粒度AIS或可重建底表。使用合法测试材料，合成权限/故障结果标注来源。

6. **布局与地图共用。** 桌面和小屏实际操作筛选浮层、图层、左侧两个模块、右侧标签和底部详情，验证可独立收起、按需展开、键盘/Esc/焦点、滚动与地图拖缩选点。复用已有布局检查，确认原地图框架、紧凑图例、实际日期和条件恢复，避免用一张设计图冒充可操作验证。
