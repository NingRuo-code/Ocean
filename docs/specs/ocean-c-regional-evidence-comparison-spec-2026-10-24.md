# Ocean C 候选区域同条件证据比较实施规格

整理日期：2026-10-24。关联既有 C #20、执行总纲 #13 与统计协议 STAT-06，承接 A #60/#71、B #72/#84 和 P0 #35。状态：已发布 [规格 #85](https://github.com/NingRuo-code/Ocean/issues/85)，标签 `ready-for-agent`；验证边界已获用户确认。发布标题：`[Spec] C 区域证据比较：同条件兼容判定、并列差异与不可比说明`。

实施任务已按用户确认发布为#86–#94：[任务与阻塞关系](../tickets/c-regional-evidence-comparison/README.md)。本行仅为本地导航，远端规格正文保持不变。

## Problem Statement

使用者希望比较几片候选海域：相同月份和公里范围下，哪里观察到更多表观捕捞活动，活动与锋面距离、冷暖侧的关系有何不同，固定海域事件后的变化证据是否一致，以及哪些差异可能只是资料覆盖或样本构成造成。

分别打开几个区域的数字不足以完成可信比较。相同字段名可能来自不同时间窗、单位、粒度、有效日期、估计量、事件规则或对照；两个区域各自可计算，也不代表二者可以直接相减。当前历史查询主要表达单点锋面频次，旧响应查询读取预汇总记录，尚不等于多区域同条件活动证据比较。

C需要在A/B已经验证的结果上建立清楚的比较合同：保留候选、逐项核对兼容性、并列已有证据、给出有依据的描述差异及不能比较的原因。它帮助使用者理解证据，不产生综合评分、成功概率或推荐排名，也不把活动密度当作鱼量、渔获或收益。

## Solution

提供显式的确定性区域比较入口：接收至少两个不同候选区域、统一月份/事件搜索期、公里半径、比较用途、方法/支持政策及已有结果身份，读取P0资格与A/B快照，形成区域×指标及需要时的区域对兼容判定。

月度空间关系与事件响应分为明确的证据板，各自在相同定义下比较小时、面积时间密度、锋面距离/侧别分布、前后/对照差、样本与区间。不能比较的格保留状态和原因，不补数、不隐式换月、不重新分析源档；只有证据足够时计算明确标为描述性的同单位差值。

输出区域位置/范围示意、并列证据表、统一单位比较图和简短解释，并能展开各区域的逐日/事件来源、支持、排除与复算依据。图、表、摘要和允许导出共享一个比较快照；工作台与AI后续消费同一结果。

## User Stories

1. 作为使用者，我希望选择至少两个不同候选区域，以便在同一任务中查看它们的证据。
2. 作为使用者，我希望区域名称与固定位置、公里范围一一对应，以便不会弄混候选。
3. 作为研究者，我希望统一月份或事件搜索期，以便明确各区域比较的时间问题。
4. 作为研究者，我希望统一研究半径和几何口径，以便范围差异不会被隐藏。
5. 作为研究者，我希望月度关系与事件响应分别展示，以便不同问题不会混在一列。
6. 作为研究者，我希望读取已验证的A/B结果，以便不重复建立科学计算引擎。
7. 作为研究者，我希望每项指标都有兼容性判定，以便同名字段不被误当同一含义。
8. 作为研究者，我希望每对区域的比较资格可查，以便新增一个缺资料区域不会否定其他可比区域。
9. 作为研究者，我希望可比、受限并列、不可比和未就绪分开，以便知道下一步是补资料还是改变问题。
10. 作为使用者，我希望不支持的区域仍保留在表中，以便看见其真实缺口。
11. 作为研究者，我希望核对实际来源、粒度和方法版本，以便精粗不同的资料不会被静默拼接。
12. 作为研究者，我希望来源快照身份可追溯，以便不同区域无需错误地具有相同内容校验值。
13. 作为研究者，我希望单位与估计量明确，以便小时、日均、密度与比例不混用。
14. 作为研究者，我希望看到实际有效面积和日期，以便相同名义半径不被误认为相同观测支持。
15. 作为研究者，我希望共同日期或标准化政策明确，以便覆盖构成差异不会伪装成区域差异。
16. 作为研究者，我希望任何限定支持后的结果保留原身份与新条件，以便不会悄悄删日或缩小样本。
17. 作为研究者，我希望距离带和侧别规则一致，以便对应组的含义可比较。
18. 作为研究者，我希望未知侧别和无法确定距离独立呈现，以便缺失贡献不从图表消失。
19. 作为研究者，我希望锋面频次只作背景，以便月度叠图不被当作同日活动关联。
20. 作为研究者，我希望各区域B事件定义及前后窗口相同，以便响应差异不来自规则改变。
21. 作为研究者，我希望知道各区域事件实际发生日期和成员，以便相对日一致不冒充同日成对事件。
22. 作为研究者，我希望各区域对照质量及未匹配比例可查，以便不同背景质量不会被忽略。
23. 作为研究者，我希望事件数量、记录行数与独立组分开，以便样本多少不被虚增。
24. 作为研究者，我希望不同区域的重叠、共享日和对照复用有提示，以便不会将其当独立重复。
25. 作为研究者，我希望后1–3日与真实后1–7日分别比较，以便短窗口不冒充完整后7。
26. 作为研究者，我希望有效零、缺测和未准备分开，以便空白不会变成低活动。
27. 作为研究者，我希望同单位描述差值有明确方向和基线，以便不会误读数字。
28. 作为研究者，我希望零或未知基线不产生无穷比值，以便比较不依赖伪计数。
29. 作为研究者，我希望保留各区域已有区间和限制，以便不能推断时仍知道证据强弱。
30. 作为研究者，我希望区域差值与正式显著性检验分开，以便现有区间不被拼成新的统计结论。
31. 作为使用者，我希望默认按候选顺序并列，以便不会被暗示存在系统推荐名次。
32. 作为使用者，我希望先看一张比较图和简短说明，以便快速理解差异与不足。
33. 作为研究者，我希望展开来源、支持、事件和方法证据，以便复核每个格子的数字。
34. 作为使用者，我希望所有图表单位、坐标与标尺一致，以便视觉差异不被独立缩放夸大。
35. 作为使用者，我希望新增或移除候选只产生新的比较版本，以便旧成果仍能解释。
36. 作为使用者，我希望改条件后旧结果保留原条件，以便不会当作新比较。
37. 作为维护者，我希望读取已有结果不启动A/B重算，以便比较界面没有隐藏重任务。
38. 作为维护者，我希望缺少源结果时返回具体前置，以便工作台后续能引导正确准备。
39. 作为维护者，我希望源结果或方法变化时缓存隔离，以便不同版本不会串用。
40. 作为研究者，我希望图表、摘要和允许导出同源，以便报告与显示一致。
41. 作为访客，我希望只读允许公开的就绪比较，以便不会获得细资料或触发受限计算。
42. 作为研究者，我希望合成兼容性测试与真实区域验证分开，以便测试通过不冒充真实证据。
43. 作为后续模块开发者，我希望稳定比较合同供工作台与AI消费，以便不再计算另一套数字。
44. 作为项目负责人，我希望C完成由真实可复算的可比及不可比路径决定，以便不要求某区域胜出或显著不同。

## Implementation Decisions

### 1. 归属、现状和真实依赖

- 本规格细化[C #20](https://github.com/NingRuo-code/Ocean/issues/20)及STAT-06，归属[执行总纲 #13](https://github.com/NingRuo-code/Ocean/issues/13)。已通过GitHub CLI回读相关正文与评论，当前均开放且暂无评论；未发现已有C实施规格。本轮没有实施比较功能或运行真实区域研究。
- 正式消费[A规格 #60](https://github.com/NingRuo-code/Ocean/issues/60)/[交接 #71](https://github.com/NingRuo-code/Ocean/issues/71)与[B规格 #72](https://github.com/NingRuo-code/Ocean/issues/72)/[交接 #84](https://github.com/NingRuo-code/Ocean/issues/84)的已验证结果、可加基础量和复算合同；P0 [#41](https://github.com/NingRuo-code/Ocean/issues/41)等提供实际用途资格。各候选还须有自己的合法支持，示范区域通过不自动放行其他海域。
- A月度板可先由合格A结果验收，不等待B所有研究完成；B板另等相应已验收事件结果。完整C包含两类证据的真实交接与比较，A-only初版不称B比较已完成。
- 软件兼容小例可以先做；真实比较必须取得对应区域的真实结果与资格，不能仅以父级Issue关闭代替。W/#21、完整AI、预测、任务中心、完整PDF及性能论文优化不反向阻塞C，不建立循环。
- 复用现有确定性服务及FastAPI验收模式，增加明确C用途/版本；现有单点历史频次与旧响应查询保持原语义。C不把旧查表重新命名成多区域研究，也不在此重写A/B统计、P0审计或几何引擎。
- ADR-0001的表观捕捞小时、精度与前后/对照原则继续适用；C只消费明确几何口径，旧移动锋面缓冲与新固定区结果不能混为一类。未批准粒度替代仍按既有ADR流程处理。

### 2. 候选、请求和比较身份

- 首批候选使用已支持的分析点与公里圆，不新增任意多边形编辑或自动搜寻“最好渔场”。请求含候选稳定标识/显示名/坐标、共同公里半径、月份或锚日搜索期、证据用途/窗口、比较/支持政策、源结果身份及规则版本。
- 至少两个不同候选；完全重复的区域/条件明确报重复，不能靠改名字当第二个独立区域，也不静默合并。相邻或部分重叠可并列，但标重叠/共享支持，不把小时/事件数简单相加。
- 保持用户提交的候选顺序，区域名只是标签，计算绑定稳定身份；不按活动值或效应自动排序，不用颜色/星级隐含推荐名次。输入非法、超支持或超过已说明的受控预算时返回原因，不悄悄删候选。
- 公共参数和逐候选实际条件分别保留。若来源快照不满足共同请求，先返回差异；不按近似同名月份、默认半径或其他可用结果自动替换。变更候选、条件、对齐或方法形成新的比较快照。
- 比较身份包含规范化请求、候选集合与展示顺序、每个源结果及资格快照、采用的支持/单位转换/聚合规则和版本。不同区域输入内容身份自然不同；兼容性要求可解释的同来源产品/语义和处理，不要求不同海域文件具有同一个内容哈希。

### 3. 兼容判定与支持政策

| 维度 | 必须核对 |
| --- | --- |
| 研究用途 | A同日月度关系、B固定区事件、背景频次分别命名，不跨用途直接相减 |
| 时间 | 具体年月/搜索期、有效日期、日界、B锚日规则和前后窗/队列政策 |
| 几何与尺度 | 公里圆/半径、真实粒度、边界归属、有效海域、距离带/侧别与误差 |
| 来源与版本 | 实际产品及含义、处理/质量规则、源结果身份、方法/参数语义兼容 |
| 指标与权重 | 小时/日均/密度/比例、H/E、事件等权或合并支持目标量、主/探索身份 |
| 有效支持 | 各区域日/面积和排除、共同日期或标准化政策、零/未知语义 |
| B对照及推断 | 事件/前后窗口规则、对照池/匹配政策、匹配率、组结构及区间适用性 |
| 可消费资格 | 真实/合成、完成/失败/旧快照、新鲜度、许可及可公开范围 |

- 兼容判定按区域×指标输出，产生跨区域差值时按区域对×指标再判定。三片海域中某一片缺资料不阻断另外两片合格比较；某项兼容不自动表示所有指标、所有区域对都兼容。
- 状态至少包括可比较、受限并列、不可比、未就绪/未核实，附机器可读原因、实际差异与所需前置。受限并列可以保留原值和限制，但不标为严格同条件或计算缺乏意义的差值。
- 语义/单位/窗口/估计对象不一致直接阻止该项算术比较；只有事先声明、可逆且语义确定的单位转换才能使用，记录原单位、转换和新单位。角度方框不通过简单乘常数冒充公里圆；粗网格不靠插值冒充研究精度。
- 方法的语义兼容依据冻结合同/参数及必要的等价证据，不只看版本字符串相同或不同；不能因名称相同放行，也不要求不同区域源内容校验值相同。兼容未能证明则受限/拒绝，不由AI猜测。
- 相同名义半径仍可能有不同海陆/有效面积。保留实际H/E和覆盖、有效日期/来源局限，不能认为除以面积后已排除全部海域、观测或活动构成差异。
- 默认保留每个原结果及其真实支持，不静默取交集、删日、删事件或改匹配。严格比较所需共同时间/支持政策必须在本次显式比较请求中登记；不具备则只受限并列或不可比。
- 若已登记的共同日期/分组政策可从许可允许的A/B逐日可加基础量实现，调用同一既有聚合合同形成独立衍生结果，报告原/新日期、H/E、排除、目标量与源身份；它不是原完整月结果，不能重新标注原快照或沿用不适用旧区间。需要新源读取、事件重识别、匹配或科学重算时返回对应A/B任务前置，不由C偷偷补算。
- 共同支持过少/未知或地区组成无法判断时降低可声称范围，门槛按P0及具体用途冻结，不在C凭空设统一覆盖百分比或强求全部区域同样有效面积。

### 4. A月度空间证据板

- 使用同一年月、公里半径与兼容A方法/支持政策，按区域并列活动总小时、同支持日均、面积时间密度、距离带/可判定侧别、有效日期/面积、同月参照效应及可用区间。总量与密度分别解释，跨区域活动更多不能自动说更集中。
- 距离带端点、最外带/未知组、侧别与单位一致；边界不同不可凭组序号对齐。细分到共同分组仅在现有可加基础量及冻结合同足以准确重聚合时允许，不拆粗组猜分布、不在图中平滑补值。
- 已知侧别与主分析的子集/分母变化单列，未知距离/侧别及排除贡献保留。SST/梯度仅消费支持的实际量，代理不称真实锋面强度，可选资料缺失不否定其他合格指标。
- 锋面出现频次、月度分布图和海温可作背景，各用正确观测分母和单位；不得以叠图代替A同日配对，也不把锋面频次当捕捞成功率。
- 各区域同月参照的空间池/支持和匹配质量列明；同名“近−远密度差”若对照问题/权重不同，受限并列而不冒充严格相同效应。季节、位置、距岸、管理与AIS覆盖等差异写入解释边界。

### 5. B事件响应证据板

- 使用兼容事件识别/锚日/合并/缺口规则、相同搜索期、固定几何和前7/后1–3/后1–7定义，逐窗比较前后及同日对照效应、实际支持、匹配与独立组。0日、持续暴露和再次进入规则按B保留。
- 各区域实际事件日期和数量可不同，表述为同一搜索期/定义下的区域事件样本；相对日相同不等于同一绝对日期，也不是同一物理锋面或自然成对样本。不存在事件对应依据时不得强配事件。
- 若比较同日或成对事件，配对目标、日期和支持必须由已有合同明确给出；无该支持只并列区域描述，不在C新增事件匹配算法或推断。
- 后1–3与真实后1–7分开，前7/后7支持、候选/入选/排除及未匹配比例可查；某区只有短窗时保留其短窗或缺口，不填后7、不以不同队列伪造时间响应差异。
- 事件等权平均、合并面积时间密度、个案与总体估计分别命名，对照域/筛选与权重、队列/相关组、可测混杂及限制一并核对。无事件、无合格对照、少独立组或退化区间均保留不同原因，不能都变成0响应。
- 跨区域可能共享日、重叠范围、事件窗口或对照，展示其已知关联与不能证明独立之处；不同区域ID不等于独立重复。C不相加各区域事件/小时作总体样本，也不借比较界面完成跨海域泛化验证。

### 6. 描述差异、区间与解释

- 可比较指标可展示清楚命名的描述差值，方向为显式选择的区域甲减乙，保留双方值、单位、H/E/样本和比较支持；不自动选择差异最大的区域对。相对差/比值仅对有效正基线定义，零或未知保留绝对差及原因，不加伪计数。
- A/B各自已有区间、置信水平、分组方法和失效状态可按原估计对象并列，区间只属于其源结果。改变共同日期、队列或权重后不能沿用旧区间，必要时显示未对新目标估计区间及重算前置。
- 区域甲减乙的描述值不是差值显著性检验；不得把两个现有区间端点简单相减、区间是否重叠或两个p值大小包装成新的正式检验。首版不新增跨区域联合重采样、成对检验或多重检验引擎。
- 若后续需要正式区域差异推断，应另行定义目标量、配对/共享支持及跨区域时空依赖，冻结联合计算和多项比较协议并验证；可复用组件如[SciPy bootstrap官方接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)要求针对具体统计量抽样，不能替代这些研究设计。此项不作为首版C完成前置。
- 对每区说明可观察差异、支持优势与局限，例如有效日更充分、某距离带活动密度较高或事件证据不足；“证据较完整”不是作业成功率，“该指标更高”不是系统推荐。少量样本、区域混杂和AIS接收/算法局限随摘要说明。
- 不输出综合分、把握度、星级、排行榜、推荐排名、渔获/鱼量/收益或因果承诺；没有差异、反向差异及不可比都正常呈现。模型/AI不能从这些数值另外推导成功概率或替用户判定最好渔场。

### 7. 执行、复用、权限与错误

- C首版是对已就绪证据的有界显式比较/只读消费，沿用A/B最小执行、状态和结果身份合同。纯读取不启动A/B、下载、归档准备、模型调用或整期重算；明确缺少哪些源结果及对应任务即可，完整编排由W/公共任务模块负责。
- 缺一项或一个区域结果时保留该列与原因，已合格部分可返回部分结果；失败与未就绪、未知与有效零分开。关键请求非法或无任何可比较区域对时返回明确受限/不可比结果，不伪装完成有用比较或生成解释性数值。
- 比较快照引用精确A/B及P0身份，所有候选、支持和兼容规则固化。改条件/增删候选后旧结果保持原条件；输入、源结果或规则变化有新身份。源新鲜度未知可按原身份读取旧成果，但不能称已获新资格或最新结果。
- 结果复用按完整身份，直接组合与复用路径在冻结容差内核对兼容状态、单位、实际支持、H/E和差值。处理失败或部分写入不得发布成完整比较，重试不能挪用其他候选结果；不新建第二缓存/任务平台。
- 本人显式计算与访客公开就绪读取按服务端许可边界投影，每个源结果分别检查，不能用一个公开区域授权覆盖全部候选。私有或授权未知成果不经比较泄露；逐日可逆细资料、原始AIS、凭据和私人路径不出现在公开返回/导出。
- 请求规模与比较区域对数量有受控预算；超限明确提示，不能无限枚举/扫归档。现有小规模可验证消费不依赖先完成P1容量实验；扩大范围另依实测资源与任务规则。

### 8. 展示、成果与后续消费

- 默认候选并列证据表、一张同单位主比较图及简短说明，月度与事件板独立标识；区域位置/公里范围示意对应稳定候选ID，原地图框架与统一条件逻辑保留，不在C重做整体界面。
- 同一指标统一单位、坐标/标尺及颜色含义，柱图等数量编码遵守合适基线；如存在局部增强或不同尺度必须显式标注，不能各区自动拉伸后并列冒充同标尺。科学配色/地图图例沿用已确认U1/U2规则。
- 不同单位指标分图或清楚分列，不叠成无含义雷达/综合优势图。区间不可用、缺测及未知使用明确状态，不绘零柱，不通过插值连线制造趋势。
- 展开详情可定位每个格子的源结果、日期/面积、候选/排除/对照/相关组、兼容判定和方法限制。无完整底表公开许可时保留受控证据定位，不能泄露私人路径以充当溯源。
- 图、表、摘要、基础聚合导出和运行清单同一个比较身份；候选顺序、指标、支持政策与版本保留，重新读取可核对。完整PDF、案例保存/保留、任务历史产品另行细化，C提供必要的稳定数据与基本可读成果。
- W/#21后续接入候选设置、显式比较、旧条件提示、图表和证据展开，并做浏览器联动；C核心可用受控入口与独立阅读产物验收，不等待完整工作台。AI只组织同一证据和限制，无模型时手动结果仍可读。

### 9. 冻结清单、阶段交付与完成关口

| 阶段 | 必须交付 | 实际前置 |
| --- | --- | --- |
| 合法小例 | 两区请求→快照读取→兼容判定→已知表/差值与证据 | 可手算合法夹具及既有确定性模式，可先准备 |
| A月度板 | 同月/半径/定义下的区域指标、实际支持及受限/不可比原因 | 对应A结果合同和区域P0资格，不等待所有B能力 |
| B事件板 | 同定义事件/窗口、对照质量、样本与区间并列 | 对应B合格结果及事件用途支持，不冒充同日成对事件 |
| 统一阅读/复用 | 分板主图/表/摘要/聚合导出同源，版本变化与部分失败不串结果 | 可验证比较合同，沿用A/B读取及身份基础 |
| 真实复算与交接 | 至少两个不同真实区域的同条件可比证据、边界路径及W消费合同 | A/#71、B/#84实际交接及各区真实资格，不能只看Issue关闭 |

- 在真实比较前冻结指标含义、时间/几何/尺度、兼容理由、支持对齐/衍生规则、区域对差值方向及展示/单位转换政策；后续改动保留版本与影响，不依据某区域胜出调整。
- 首选已登记东海2024-08相关A/B证据，候选位置依据实际支持而非活动高低选择；具体候选与兼容阈值据P0和可读结果确定，不在本轮捏造真实区域资格或推广任意海域。
- 完整C须有至少两个不同真实区域的可复算比较，A月度板与B事件板各有真实合格可比实例，保留实际请求、源身份、支持/样本、解释和允许导出；可分批验收，某板未就绪不勾选该真实验收。
- 相同数值或无稳定差异仍可通过。某真实候选不合格时保留原因和解除条件，不以删除它、用同一区改名或合成第二域假装满足；只交不可比说明可以完成相应软件路径，但不能充当真实可比实例已取得。
- 兼容、受限、不可比、缺测/零、重叠/重复、版本冲突和部分失败路径均有独立已知答案，真实资料不必恰好包含每种负例，可明确标注合成补充。
- 软件能力、真实比较关口、PR、合并和部署分别记录；不修改或关闭#20/#13及A/B父级。此轮仅整理规格，未执行真实区域比较、科学检验、应用测试、生产压测或部署。

## Testing Decisions

### 1. 已确认的主要验证入口

以“显式提交区域比较请求→读取实际A/B快照与资格→逐项兼容判定/同合同组合→同身份结果和证据”为主要端到端入口，优先沿用现有FastAPI测试客户端、确定性查询/受控计算及A/B结果消费合同。结果图表与导出在同一身份下核验，不新建测试专用业务接口。

独立手算多区域小例验证指标/单位、时间/半径/版本冲突、共同日期/队列、H/E、零/未知、部分失败和描述差值。真实至少两个不同区域的A月度与B事件比较另行复算记证，与合成合同测试分开；工作台浏览器联动在#21后续验收。

用户已于2026-10-24确认上述边界：显式区域比较请求验证实际A/B快照读取、逐项兼容判定及同身份结果/证据；独立手算多区域样例核对单位、月份/半径/版本冲突、有效支持、零值/缺测、部分失败及描述差值；至少两个真实区域的A月度与B事件比较分别复算，与合成测试分开记证；复用现有API/受控入口，工作台浏览器联动在#21后续验收。先前UI、P0、P1、A和B验收继续各自适用，不当作C已通过。

### 2. 好的测试与既有基础

- 验证请求与实际区域/条件、源结果引用、可比/受限/不可比理由、单位与估计对象、支持/分子分母、值/差值与消费同源，不绑定内部目录、字段顺序、图表DOM或函数拆分。
- 复用现有确定性查询缺测不报零/部分结果/来源身份检查，及A/B交接的直接参照、只读、版本与结果消费检查；旧单点历史频次和预汇总事件断言不充当C的科学正确性预期。
- 合法已知快照由独立手算/固定事实构造，预期兼容理由和差值不由被测比较器自己生成；对支持衍生独立核对原/新日期与H/E，不只对比两个共用同一错误聚合的路径。
- 不以地区胜出、区间不重叠、显著或更高活动作为验收。C不新做跨区域推断，测试要证明无依据的差值/显著标签不会生成；真实与合成、未核实与未执行分别记录。

### 3. 必须覆盖的场景

| 场景 | 可观察验收 |
| --- | --- |
| 至少两区/重复与重叠 | 完全重复不伪造独立候选，重叠提示共享支持，身份与名称不串 |
| 月份/半径/几何冲突 | 逐项列差异，不换条件、不把角度方框当公里圆 |
| 来源/粒度/方法差异 | 按实际语义与等价证据判定，不只比版本名或内容哈希 |
| 同名不同指标/单位/权重 | 阻止不合法相减，批准转换留证，总量/密度/事件均差不混 |
| 海岸/有效面积/日期不同 | 支持真实显示，明确限定并列与共同支持要求，不补未知为零 |
| 已登记支持衍生 | 精确复用可加基础量，新身份与原/新范围可查，不沿用错误旧区间 |
| 距离带/侧别/可选层不一致 | 不能按序号硬拼组，未知贡献与子集变化可查，其他指标仍可读 |
| B不同锚日/窗口/队列 | 相对日不冒充同日成对，后3不填后7，事件成员与对照限制清楚 |
| 三候选中一项失败 | 保留失败列，其他合格区域对仍可比较，不错误全局放行/否决 |
| 零、未知及相对基线 | 有效零与未准备分开，无假零柱/无穷比值/伪计数 |
| 重叠/共享对照与区间 | 不虚增独立样本，不拼区间成显著差，不相加重复小时/事件 |
| 重排/增删/换源/规则变更 | 稳定ID、旧快照条件明确，新身份隔离，读取无隐式重算 |
| 图表/摘要/导出与权限 | 同单位标尺和数值，原身份可追溯，私有或未知授权内容不泄露 |
| 真实可比及无差异实例 | 至少两真实区域可复算，A/B板分别记证，无胜出要求，合成不冒充 |

### 4. 真实验收证据

- 保存真实候选、原/实际条件、A/B及P0身份、各指标/区域对兼容理由、支持与排除、衍生或转换、H/E/样本/已有区间、图表和复算清单；私有底表留在许可允许存储。
- 同输入直接组合、缓存/复用及允许导出核对冻结数值容差与条件；源无法核实或新鲜度未知明确显示，旧结果不充当新资格。
- 实施时按影响运行后端、数据和必要结果消费回归；#21集成再做浏览器操作，性能容量/新联合检验单独验收。此轮文档检查不填写真实比较或科学通过结论。

## Out of Scope

- 新建A月度关系或B事件/对照/相关组统计引擎、P0来源审计/几何/资格系统；必要重算返回既有任务前置，不由C隐式执行。
- 跨区域新的正式联合检验/因果识别、多重检验、解释模型、G3跨年份/季节/海区独立复核及相似事件检索。
- 综合评分、捕捞成功率、推荐排名、自动搜寻最好渔场、鱼量/渔获/收益推断与活动预测训练或增量验证。
- 任意多边形编辑、地图框架重做、完整AI/自然语言编排、完整任务中心/恢复、案例库/PDF产品化或身份平台；C保留必要读取/执行/许可边界与稳定消费合同。
- P1论文系统/数据库或渲染优化、硬件采购、未批准下载/付费数据、受限资料公开、自动关闭父级、合并、部署或生产压测。
