## Problem Statement

使用者需要系统在现有服务器上可靠运行：地图与分析使用正确版本，耗时任务不挤占普通浏览，已保存成果能重开，更新失败可以退回，主机或存储发生故障后有经过验证的恢复办法。项目负责人还需要明确区分本地通过、合并、已部署、实际线上验证和完整研究成果交付。

仓库已有部署手册、应用上传/安装、服务与代理配置、容量盘点、公共冒烟及测试实例。它们尚不能证明完整的版本化交付、维护监测或灾难恢复：现有上传以工作目录打包并原位解包，回退主要切代码；测试实例复用生产代码、环境与源资料；公共代理模板对API统一声明公开缓存；现有健康响应只说明服务能回答。未发现覆盖任务、案例、保护引用、接触台账及AI状态的一致备份与隔离恢复闭环。

TASK的安全续跑不等于整机或持久存储恢复，PDF能下载也不等于科学结果及必要引用已受到可恢复保护。OPS需要把已有模块接成可核对的交付和维护流程，避免旧代码配新状态、测试触碰生产、缓存泄漏私人结果、更新破坏旧成果或恢复后重复执行和收费。

## Solution

在既有服务器和部署路径上建立可核对的发布单元、独立验收环境和受控切换流程。每次发布绑定已审核提交、前后端资产、运行环境、合同/配置及允许的数据范围，先验证再切换；失败时按兼容方案回退，保留已有任务和成果，不用旧代码覆盖新状态冒充恢复。

复用既有轻量健康、数据清单、任务状态和资源观察，区分进程存活、服务就绪、资料就绪、研究资格与数据实际日期。对容量、失败、准备停滞、备份过期等提供本人可查的脱敏状态与有界告警；访客保留公开且就绪的地图和合法结果，私有操作及在线模型沿原权限与安全访问方式。

按轻量状态、受保护成果、可再生产物和源资料分别制定备份及保留政策。取得允许的备份位置、访问和容量条件后，实际生成一致备份、保存与服务主机故障隔离的合法副本，并在独立环境恢复，验证原任务/结果/案例/文件及权限和接触边界。基础发布与恢复可先从小范围A闭环推进，B/C、G3/PRED、报告及AI按各自真实交接纳入，最终形成有明确范围和欠项的完整交付记录。

## User Stories

1. 作为访客，我希望已公开地图和就绪成果持续可读，以便了解系统能力。
2. 作为本人，我希望知道当前实际部署的版本和支持范围，以便判断正在使用哪套功能。
3. 作为负责人，我希望代码、数据、合同和研究结果版本分别可查，以便不把部署时间当观测时间。
4. 作为维护者，我希望每次发布来自明确审核提交，以便不会混入工作目录中的私有材料。
5. 作为维护者，我希望发布资产有完整性和运行环境记录，以便另一台环境可按同一版本启动。
6. 作为维护者，我希望测试和生产的可写状态相互隔离，以便检查不会损坏线上成果。
7. 作为维护者，我希望测试代码和依赖也独立固定，以便修改测试环境不会改变生产行为。
8. 作为本人，我希望发布时已有任务保留原条件和正确状态，以便不丢失正在进行的研究。
9. 作为本人，我希望维护期间知道哪些操作暂不可用，以便仍能继续允许的浏览。
10. 作为维护者，我希望发布前有可复核的准入检查，以便不靠一次健康返回判断成功。
11. 作为维护者，我希望前端、接口和执行进程属于兼容发布，以便旧页面不会误用新合同。
12. 作为维护者，我希望发布失败可退回已知可用版本，以便缩短故障影响。
13. 作为维护者，我希望回退先检查持久格式兼容性，以便不会损坏新版本产生的状态。
14. 作为本人，我希望回退后已完成结果仍可阅读，以便不用为恢复页面重复计算。
15. 作为本人，我希望服务重启按TASK规则恢复或中断任务，以便不会重复步骤和发布半成品。
16. 作为维护者，我希望旧执行进程不能提交恢复后结果，以便避免多代进程竞争。
17. 作为使用者，我希望看到真实资料日期、覆盖和未知状态，以便历史资料不被误称为今天。
18. 作为本人，我希望历史资料补齐和质量更新有明确范围和记录，以便不会默认全档采集。
19. 作为本人，我希望准备后的资料先经校验再可见，以便失败文件不会进入研究。
20. 作为本人，我希望资料更新后旧结果仍保留原版本，以便继续核对原结论。
21. 作为使用者，我希望缺测、零值、未准备和服务故障分开显示，以便正确理解不可用。
22. 作为本人，我希望资料就绪与研究资格分别说明，以便不把下载完成当整月或事件可分析。
23. 作为维护者，我希望缓存依据实际版本和权限失效，以便不串用旧科学值或私人内容。
24. 作为本人，我希望私人任务、案例、对话和文件不进入公共缓存，以便公开演示不泄漏研究内容。
25. 作为访客，我希望公开访问边界由服务端实施，以便合法浏览不会绕过后台权限。
26. 作为本人，我希望后台凭据和在线模型调用经受控访问，以便不会从匿名演示路径暴露。
27. 作为维护者，我希望轻量存活检查和业务就绪判断分开，以便快速定位故障层。
28. 作为维护者，我希望能查资料、任务、存储和备份状态，以便不必把敏感日志贴进项目。
29. 作为维护者，我希望监测本身有开销上限，以便不会触发扫档、研究或模型费用。
30. 作为维护者，我希望告警包含可操作原因和最近成功时间，以便及时处理有效问题。
31. 作为维护者，我希望告警去重并能记录恢复，以便不被重复消息淹没。
32. 作为本人，我希望维护通知保持简短，以便不让地图界面重新变得臃肿。
33. 作为负责人，我希望容量结论来自实际工作集，以便知道现有服务器支持到什么范围。
34. 作为维护者，我希望重任务、地图、备份和维护共享真实资源预算，以便后台工作不挤停浏览。
35. 作为维护者，我希望磁盘或内存不足时拒绝新工作并保留旧成果，以便不会靠删重要资料解决。
36. 作为维护者，我希望源档、缓存、普通产物、保护成果和备份分别计量，以便保留策略不会混淆。
37. 作为本人，我希望明确哪些状态和文件受备份保护，以便知道故障后能恢复什么。
38. 作为本人，我希望主动保存案例及必要文件可一起恢复，以便不会只恢复一条空记录。
39. 作为维护者，我希望备份是同一可核对时间点的状态与引用，以便不会恢复出不存在的成功结果。
40. 作为维护者，我希望备份有清单、校验和完成状态，以便损坏或未完成副本不会被当作可用。
41. 作为维护者，我希望备份失败保留上一份可用副本，以便不会在故障时失去全部恢复点。
42. 作为维护者，我希望至少一份合法副本与服务主机故障隔离，以便主机丢失后仍有恢复依据。
43. 作为本人，我希望备份的权限和复制位置遵守原资料许可，以便数据不会因备份被公开或外传。
44. 作为维护者，我希望恢复密钥和凭据有独立受控办法，以便备份文件存在时确实能读取和启动。
45. 作为负责人，我希望允许数据损失范围和恢复时间目标被明确并实测，以便判断保护程度是否足够。
46. 作为维护者，我希望在空白隔离环境实际恢复，以便验证备份而非只验证打包成功。
47. 作为本人，我希望恢复后能重开原任务、结果和报告，以便继续研究和复核。
48. 作为维护者，我希望恢复演练默认停止外部发送和自动执行，以便不会重复下载、分析或收费。
49. 作为研究者，我希望恢复旧备份不会把已接触目标变成未见，以便独立验证仍可信。
50. 作为本人，我希望撤销权限和许可不会因恢复旧状态失效，以便历史备份不能重新开放受限内容。
51. 作为本人，我希望模型费用和请求不明时恢复过程保守停用，以便不会自动重复已计费调用。
52. 作为维护者，我希望丢失或损坏的依赖明确标出，以便不能恢复的内容不会显示成功。
53. 作为维护者，我希望备份清理有单独规则，以便普通产物清理不会删除最后可用恢复点。
54. 作为负责人，我希望恢复演练记录实际版本、时刻、范围和限制，以便评估真实保护能力。
55. 作为本人，我希望报告、案例和AI解释始终引用同一原结果，以便系统整合不会制造新数值。
56. 作为负责人，我希望各研究工具逐项纳入联合验收，以便基础运维不等待所有科研完成。
57. 作为负责人，我希望完整研究版能回放数据到任务、图表、解释、保存导出的链路，以便交付范围明确。
58. 作为负责人，我希望真实成果、合成故障、测试环境和生产证据分开，以便不会混淆完成程度。
59. 作为维护者，我希望生产发布只按已审核版本和另行安排执行，以便规划或合并不自动变成部署授权。
60. 作为维护者，我希望交付手册与实际可运行操作一致，以便下一次更新和恢复可重复。
61. 作为维护者，我希望日志和公开证据不包含凭据、服务器地址或受限源细节，以便便于安全协作。
62. 作为负责人，我希望尚未验证的规模、研究和运行条件继续列为欠项，以便不夸大系统能力。
63. 作为负责人，我希望域名、HTTPS、服务器升级按场景和实测安排，以便不会盲目采购或迁移。
64. 作为使用者，我希望离线演示和手动功能仍可用，以便服务或模型故障时保留已支持的阅读能力。

## Implementation Decisions

### I01 归属与分批交付

- [ ] 归属OPS/G5及#13，复用既有#10/#11/#12部署交付基础与P0/P1、W/TASK/REPORT、G3/PRED和AI合同；不修改或关闭父级，不重建科学引擎、任务恢复、案例、权限、资料审计或模型平台。
- [ ] 基础发布身份、隔离环境、监测和小范围备份恢复可先交付；各工具按实际可用合同接入，不能把#108/#124/#140/#158/#175/#198/#225所有收官任务设成每项OPS的统一前置。
- [ ] 最终范围以发布能力清单逐项列明：软件与小例、真实资料/科研、服务整合、生产准入和线上验证分别判定。基础A闭环不冒称完整研究版，缺真实B/C/G3/PRED或AI证据时对应整合项保持未完成。
- [ ] 本轮仅整理规格，后续实现/检查/PR、用户审核合并、实际部署分别安排；规格批准或Issue关闭不授权自动修改生产、上传资料、采购、压力测试、故障演练或产生模型费用。

### I02 实际盘点与发布单元

- [ ] 先核既有服务器角色、服务/代理/执行进程、持久存储、源/热数据/缓存/成果/备份体量和访问方式，消费#47已有盘点；缺访问或资料明确未知，不把模板的worker数/内存或旧注释当现服配置。
- [ ] 发布单元绑定审核提交及内容身份、前后端资产、必要脚本/模板、运行时/依赖解析版本、合同/状态格式与非敏感配置版本，附完整性清单及本地实际检查；无Git目录的上传包也能核对真实运行身份。
- [ ] 应用打包采用明确允许内容及泄漏检查，不直接打包整个工作目录后仅排除少数目录；受限源档、凭据、私人文件、临时报告/日志、工作区其他改动不随代码发布，数据更新走独立合法清单。
- [ ] 构建/安装失败不切换，保留可重用的已验运行环境及依赖依据；不能靠再次无界升级依赖声称可复现，不因旧安装脚本顺带装库就认定新任务体系必须采用该数据库。

### I03 验收环境与故障隔离

- [ ] 复用既有测试实例和代理模式，固定独立发布代码、静态资产与运行环境；测试和生产不得因共享工作目录/虚拟环境修改而互相更新。是否容器化服从现有设施，不强制引入新平台。
- [ ] 测试任务/案例/对话/接触记录、索引/缓存/输出/备份暂存和执行租约独立，故障演练不得追随链接写入生产源或共享状态；共享合法输入仅在可证明只读且版本固定时允许。
- [ ] 演练默认隔离外部写入、真实模型发送、采集调度和公开发布，采用合法小范围材料与测试凭据，独立身份/预算不复用生产会话。需要真实外部操作时另按既有实际许可和受控计划执行。
- [ ] 环境标识、端口/路由、进程归属及存储边界可核对，错误目标即拒绝操作；终止/清理只作用已登记目标，不依赖宽泛进程匹配或任意路径删除证明隔离。

### I04 公开入口、私有访问与缓存

- [ ] 公开匿名入口继续服务已准许的就绪地图/轻量读取；本人提交/准备/取消重试、私有任务/成果/对话、在线模型和维护接口沿W/AI实际服务端权限，代理层不能变成绕过原权限的替代。
- [ ] 区分公开静态资产、允许公开且版本明确的聚合读取、私人/权限相关响应及维护/错误响应；不得对全部API统一声明public缓存。私有内容和认证状态不进入共享缓存，旧缓存命中与直接文件访问仍核当前权限。
- [ ] 本人凭据、私有操作和在线模型只经已验证的受控安全通道，可复用现有隧道/专用访问或已就绪HTTPS；未具备时公开HTTP仅提供允许匿名范围，不强迫先购域名，也不能把隐藏按钮当保护。
- [ ] 后端/测试/维护进程不因发布暴露额外公网端口，访问方式、可信代理/来源和会话策略与实际认证一致；日志/错误/健康返回不含密钥、私人路径、地址或受限数据详情，生产策略须实际经入口核验。

### I05 版本可见性与资产兼容

- [ ] 已有健康/能力和页面数据状态以最小增量公开安全发布身份、实际就绪范围及合同兼容状态；私有配置/运行明细仅本人查阅，不新建臃肿常驻运维面板。
- [ ] 前端资产、接口/执行进程与持久格式有可检查兼容矩阵；旧标签页请求遇不兼容明确要求刷新/停止新提交，不自动按新参数重放旧意图或把旧结果放在新标题下。
- [ ] 静态资产按内容/发布身份复用，入口文档能发现新版本；后端缓存继续绑定源/支持/方法/合同与权限，不仅按发布日期或文件路径判断。不得用清空全部缓存掩盖版本混用。
- [ ] 发布记录区分构建、激活、观测、数据处理与结果生成时间，历史资料不称今天；服务进程实际加载版本与磁盘代码版本分别核对，配置文件替换不能冒称进程已更新。

### I06 受控发布与运行任务衔接

- [ ] 部署按预检→合法包校验/暂存→配置/格式兼容检查→隔离冒烟→受控激活→入口验证→结果登记执行，阶段/退出状态可核对；不能以日志含某字符串、后台启动或脚本退出0代替发布成功。
- [ ] 切换前控制新重任务受理并核正在执行/发布的工作，沿TASK原租约、检查点和状态合同等待安全点或准确中断；轻量读取可在已支持范围继续，不能固定短超时后强杀并假称可恢复。

## Testing Decisions

主验收接缝已获用户确认：采用同一真实交付链：“审核发布单元→隔离环境实际部署/切换→真实浏览器与原API核条件/任务/结果/文件→实际回退或由合法备份恢复→再次读取同身份成果及权限”。沿现有部署、冒烟、任务/成果服务和浏览器检查验证，不为测试新建业务入口。破坏性或资源故障只在隔离环境，生产验证只在后续单独安排的合法范围执行。用户已确认以下验收边界。

1. **发布而非仅安装。** 用两个可区分且兼容性明确的实际发布单元验证完整性、运行身份、资产/接口一致、旧页面与缓存、受理暂停/恢复、失败不切换和回退。用独立小例/原结果核字段、单位/支持和文件，不仅核服务active、日志字符串或HTTP200。
2. **隔离证明。** 核实际代码/依赖、持久状态、图/索引/缓存/输出、任务租约和凭据/外发目标；在隔离环境真实修改/终止指定组件、损坏暂存或模拟磁盘不足，确认生产材料未被写入。共享输入若不可证明只读/固定身份则不用于破坏演练。
3. **回退与TASK衔接。** 实际覆盖激活前后、任务执行/发布与回写之间、取消已记录和旧执行者迟到；核兼容回退、不兼容拒绝、安全续跑或正确中断、原完成结果不丢和幂等。复用TASK已有故障证据，只补跨发布/恢复代际风险，不能仅用模拟状态代替真实操作。
4. **真实备份和独立恢复。** 用实际任务/案例/保护依赖及可下载报告的小范围合法状态生成一致备份，实际保存并取回一份与主机故障隔离的允许副本，在空白隔离环境恢复；通过浏览器重开原条件、结果、案例/文件并核校验与数值。至少一份真实合法研究成果纳入，合成故障可补损坏/缺依赖；有备份文件但未恢复不算通过。
5. **恢复边界反例。** 独立已知时间线覆盖备份后完成/取消、权限撤销、科研目标接触、同源改版及外部计费未知，核恢复后保守禁用/中断和对账，不重做已完成步骤、不恢复虚假未见、不重复模型调用。真实任务存储和原合同操作为主，替身外部供应方只用于验证未发请求，不能替代真实费用/模型模块本身验收。

7. **监测和有界资源。** 在受控环境模拟服务不就绪、源不更新/延迟、任务停滞、备份过期、策略/采样失效和容量阈值，验证分类、最近成功时刻、去重/恢复及无采集/模型副作用。按P1/TASK同环境协议测OPS新增备份/恢复与读写混合负载，记录实际峰值/停止条件，不未经安排压测生产或宣称全部性能达标。
