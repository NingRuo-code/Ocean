# Ocean P0 数据审计与分析条件合同实施规格

整理日期：2026-10-24。关联既有 P0 #14 和执行总纲 #13；本规格细化原工作包，不新增另一轮数据总任务。用户已确认验证边界，已发布：[规格 Issue #35](https://github.com/NingRuo-code/Ocean/issues/35)，标签 `ready-for-agent`。发布标题：`[Spec] P0 数据审计与分析条件合同：覆盖、粒度、零值、版本与支持范围`。

实施任务已按用户确认发布为 #36–#44：[任务与阻塞关系](../tickets/p0-data-contract/README.md)。本行仅为本地交付导航，不修改远端父规格正文。

## Problem Statement

使用者希望选择海域、地点、公里范围和月份后，知道系统能否分析锋面与捕捞活动的关系，以及数字是否可信。目前“目录里有文件”“日期清单列出该日”“接口能够返回”和“所选区域存在有效且共同可用的资料”尚未被完整区分。界面能展示单日资料，不代表完整月研究、任意位置小半径分析或事件前后窗口已经具备条件。

已有审计记录锋面和 SST 各 62 个逐日文件、旧响应表 186 行，但没有证明逐日 AIS 共同有效覆盖及 0.01°研究真源；旧表也没有可用后七日小时字段。本地、服务器、离线导出之间的版本身份尚不足以互相核对。原始资料、展示聚合和已有事件表若混用，会造成错误分母、把未知当零或将粗粒度结果误称精细观测。

P0 必须先回答“有什么、实际含义是什么、哪里何时能用、能支持哪类问题、缺什么证据”，为后续统计、显示与性能工作提供共享合同，不能以得到正向锋面关系作为数据验收目标。

## Solution

复用现有本地审计、资料清单、日期索引和数据读取能力，形成可复跑的逐层逐日审计链。它输出可脱敏的来源登记、完整日历覆盖台账、实际粒度与零值语义、版本身份、分析条件合同和支持判定；每项结论能追到具体证据层级。

对相同的地点、公里圆、月份、分析用途和版本，给出“支持、有限支持、暂不支持或未核实”，说明有效日期、有效空间支持、所用分母、缺口及可执行的下一步。地图阅读、描述统计、正式 A 分析和 B 事件窗口分别判断，不用一个笼统的就绪布尔值替代。

首选核实东海 2024-08 完整日历月，并检查相邻日资料对前后窗口的支持。若不具备研究条件，交付明确的缺口证据和后续前置；不补零、不降低粒度要求、不把其他月份默认为替代成功案例。

## User Stories

1. 作为研究者，我希望查看锋面、SST 和活动资料的真实来源，以便了解每项数据能回答什么问题。
2. 作为维护者，我希望区分研究真源、展示聚合和预计算响应表，以便后续分析不误用地图数据。
3. 作为研究者，我希望核对本地、离线导出和服务器的数据身份，以便判断它们是否属于同一资料版本。
4. 作为研究者，我希望每份来源记录产品、单位、处理方式和证据，以便追查异常数字。
5. 作为维护者，我希望许可和公开边界按实际产品及获取渠道核实，以便不将代码中的默认标记当作已确认授权。
6. 作为研究者，我希望看到完整月份的逐日台账，以便发现日期清单掩盖的缺日或坏文件。
7. 作为研究者，我希望文件存在、可解析和有效观测分开记录，以便不把文件数量当作覆盖率。
8. 作为研究者，我希望文件名、内容日期和时间坐标相互核对，以便避免同日错配。
9. 作为研究者，我希望发现重复、冲突或不同版本的同日资料，以便不重复累加或任意择一。
10. 作为研究者，我希望联合覆盖按所需图层交集计算，以便不以单层年限代替所有资料的共同年限。
11. 作为使用者，我希望知道所选公里圆的实际支持情况，以便不将整个返回区域的统计当作本地结果。
12. 作为研究者，我希望有效面积和日期都有依据，以便比较距离带或区域时使用正确分母。
13. 作为研究者，我希望 AIS 有效零、无记录和覆盖未知分开，以便不把未知区域当作没有作业。
14. 作为研究者，我希望读取失败、权限不足、未准备和产品无覆盖分开，以便采取正确补救方式。
15. 作为维护者，我希望审计发现适配层自动补的值，以便区分源字段和程序缺省。
16. 作为研究者，我希望核对实际网格坐标、步长和空间语义，以便不只依赖文件名或声明的分辨率。
17. 作为研究者，我希望 0.01°分析目标和 0.1°展示数据的差异显式保留，以便不误认为研究精度已经达标。
18. 作为研究者，我希望网格中心、格边及来源范围含义明确，以便正确处理圆域边界。
19. 作为研究者，我希望 SST 单位、填充值及缩放规则可追溯，以便避免把无效值或单位转换错误用于分析。
20. 作为研究者，我希望 AIS 小时、重复格和异常值得到核实，以便不重复计时或错误限制多船累计时长。
21. 作为研究者，我希望地图视野、分析公里圆和锋线缓冲分别定义，以便同一界面条件不产生不同计算含义。
22. 作为研究者，我希望边界格归属和重叠缓冲去重有冻结规则，以便结果可以复算。
23. 作为研究者，我希望未知侧别保留为未知，以便不把无法判定的格强行分到冷侧或暖侧。
24. 作为研究者，我希望月度支持判定说明质量规则及其版本，以便不靠隐藏缺日满足“完整月”。
25. 作为研究者，我希望检查月边界之外的前七日及后续窗口，以便事件分析不会用不完整资料。
26. 作为研究者，我希望前后窗口的总量、日均和面积时间密度分开，以便不直接比较七天总量和三天总量。
27. 作为研究者，我希望零分母和零基线有明确处理，以便不出现伪精确百分比、无穷大或假零。
28. 作为使用者，我希望同一地点、月份和半径得到一致的支持理由，以便地图、工作台和未来分析工具不会各说各话。
29. 作为研究者，我希望原始与聚合层之间有小时守恒核对，以便展示加工不改变统计含义。
30. 作为研究者，我希望来源或处理规则变化会产生新身份，以便旧结果不被悄悄改写。
31. 作为维护者，我希望清单声称存在但无法读取的资料被指出，以便修复目录或归档准备问题。
32. 作为研究者，我希望能够复跑一个手工可核对的小例，以便确认几何、分子和分母的含义。
33. 作为研究者，我希望审计报告区分真实资料和合成夹具证据，以便不会把测试成功当作真实研究就绪。
34. 作为维护者，我希望正常查询读取已生成的轻量结果，以便不因打开页面而反复扫描多年归档。
35. 作为访客，我希望只看到可公开的支持摘要，以便不暴露原始资料、服务器目录或受限网格。
36. 作为研究者，我希望资料不可访问时得到明确的待核实结论，以便不把没有权限解释为资料不存在。
37. 作为维护者，我希望同一批输入重跑得到一致的实质结论，以便检测审计和版本错误。
38. 作为研究者，我希望数据不足时得到明确的缺口与可解除条件，以便安排后续补充工作。
39. 作为研究者，我希望知道哪些半径只适用于展示、哪些满足研究条件，以便不把现有界面档位当作精度证明。
40. 作为项目负责人，我希望审计完成和研究关口通过分别登记，以便任务进度不会掩盖数据仍不足。

## Implementation Decisions

### 1. 工作包边界与当前证据

- 本规格细化 [P0 #14](https://github.com/NingRuo-code/Ocean/issues/14)，隶属 [执行总纲 #13](https://github.com/NingRuo-code/Ocean/issues/13)，承接 STAT-01/METHOD-02。复用现有审计和数据索引，不另建重复的总体数据任务。
- 已读取 #14 最新正文与评论；该 Issue 仍实施中，暂无评论。其历史记录包括 62 日锋面/SST 文件、186 行旧响应记录且后七日字段无有效行，以及一次 0.1°活动日接口读取。这些是历史证据，不是本轮重新运行审计或线上逐日验证的结果。
- 当前 manifest/索引偏重文件及日期配对，未完成 AIS 联合有效覆盖。部分已有路径会为缺少的小时、粒度或范围补默认值，部分温度解码允许启发式判断单位；审计不得将这些缺省或推断冒充源证据。
- P0 只实现数据资格与分析条件合同及其小例，不计算正式 A/B/C 科学结论、不训练预测模型。界面改造、请求正确性、性能基线可并行；资料支持结果按用途供其消费。

### 2. 来源登记、证据等级与版本

来源登记至少包含以下逻辑信息；具体存储结构沿用并扩展现有实现，不要求另建数据库：

| 内容 | 必须记录的含义 |
| --- | --- |
| 产品与角色 | 产品/获取渠道、变量、单位、研究真源或展示/预计算用途、空间及时间定义 |
| 来源和处理身份 | 产品版本/快照、原始证据身份、转换与聚合版本、源到产物关系 |
| 空间支持 | 坐标系、实际坐标/网格步长、格中心/边界语义、范围、陆海掩码及有效性证据 |
| 时间支持 | 观测日和日界依据、时间坐标、文件名/内容一致性、可核实的日期及窗口 |
| 质量与缺省 | 有效范围、缺测/填充值、异常和重复规则；字段原有、规范化、推断或缺省的来源 |
| 使用边界 | 来源许可证据、署名、可访问范围、可用于内部分析/公开展示的范围及未决冲突 |
| 复查记录 | 审计时间、执行与协议版本、检查范围、输入身份、结果及失败/未核实原因 |

- 证据等级至少区分清单声明、实际可读、结构/语义核实、有效支持核实；不得因名称相同自动提升等级。同一审计条目可分别具有已证和未知字段。
- 本地、离线、服务器各自记录来源身份，部署提交和数据版本分开；健康正常不能证明部署提交相同。服务器不能提供身份时登记未知及复核途径，不编造版本。
- 使用稳定的资料身份及内容证据核对变更；大小/修改时间可用于发现变化，不能单独证明内容完全相同。大归档可复用既有可靠校验记录，避免每次轻量读取重新扫描全部字节。
- 产品只提供 latest 时，记录取得快照、获取时间及可得内容身份；不能把动态名字当不可变版本。同输入及同协议重跑的实质结果一致，生成时间单列，不让时间戳独自改变数据身份。
- 已发现来源代码的许可标记与治理文档不一致。P0 按具体产品、渠道与当时条款收集原始证据并登记冲突；本规格不裁定哪一标记正确，不自动扩大公开许可。证据不足时限制相应用途，保留内部排查记录。

### 3. 完整日历、逐层逐日与联合覆盖

- 首选候选为东海 2024-08；所有日历日均有台账，包括清单未列出的日期。核对锋面、SST、活动的清单、实际可读数据和内容日期，不只抽查一天或统计文件数。
- 区分来源产品无覆盖、归档存在但未准备、当前无法访问、文件缺失、解析失败、内容冲突、有效零、部分有效和覆盖未知。抓取或解析失败不抹成缺日，更不补零。
- 多时次或多日 SST 文件按实际时间坐标登记；日界/时区按产品说明，不能把用户界面时区作为观测日定义。文件名与内容不符、重复快照及跨日冲突应可定位并说明处理，未解决冲突不能自动计入正式支持。
- 每日记录请求区域、产品声明域、可读取域、各层有效支持和用于该用途的共同支持。存在记录的 bbox、接口默认 bbox 和活动非空格不能单独证明整个海域被有效观察。
- 联合支持按分析用途必需图层求交：锋面—活动关系必须具备这两层所需支持，使用 SST 分组时才额外要求对应 SST；可选强度或海况未接入不必阻塞不使用它们的分析。不得一律要求所有潜在图层齐全，也不得漏掉当前分析必需层。
- “完整月审计”指全日历已检查且缺口披露；“可用于正式月研究”还需实际共同支持满足冻结质量规则。逐日数、有效面积、未知面积和排除原因分别报告；覆盖阈值未核实不能直接给正式通过。
- 不确定的覆盖分母保持未知；AIS 接收、船型识别和行为分类限制随结果保留。即使来源数据完整，AIS 指标也不代表海上所有实际捕捞被观察。
- B 后续窗口单独列资格：固定区域前 7 日、后 1–3 日、后 1–7 日及事件日处理按协议登记，包括所需相邻月份日期。不从后 3 日推后 7 日，不因单月 A 合格就宣称 B 合格。

### 4. 零值、无记录、错误与质量

- 使用独立维度表达资料可用性、观测/覆盖状态、值有效性和用途资格；不强行把“零”与“权限不足”等含义压在一个互斥状态里。返回面向调用方的一致状态、原因、证据及当前身份。
- 活动小时显式有限非负零可作为来源报告的记录零，保留其覆盖局限；字段缺失、null、NaN、解析失败和无记录不能经默认转换成为有效零。相同规则约束清单汇总和 API 规范化输出。
- 稀疏源中未出现的格，只有具体产品/处理语义明确保证所需域及零值意义时，才可映射为该指标零；仍保留证明。不能通过把稀疏数组铺满零获得覆盖掩码。
- 核对正值、负值、非有限值、重复格、多版本重复和时间重复。负小时等异常按质量规则排除并计数，不能静默截为零；多船累计大于 24 小时不自动视为错误。
- 旧处理采用重复格取最大、缺失置零或邻格匹配时，保留实际来源/匹配偏移，比较源与产物，必要时阻止相应研究资格；不将邻格匹配说成目标格精确观测。
- SST 记录源单位、转换、有效范围、填充值、缩放/偏移和掩码；未证实单位时启发式值只能标为推断，不支持正式单位一致性结论。锋面无检出与锋面层缺测分开，未知侧别不默认为冷或暖。
- 合法格式、单日内容与汇总分子核对；网格源到展示聚合核对小时守恒及容差。既有全域接口总小时不能当局部公里圆总量。P0 不要求为此重建全部展示加工链，但必须报告不一致和阻塞影响。

### 5. 粒度、几何和分母合同

- 分别登记 ADR-0001 的 0.01°分析目标、现有 0.1°活动展示资料、0.05°锋面/离线展示及实际 SST 原资料粒度。核实网格坐标与源产品，不能以参数可传 0.01°、字段默认值或插值文件证明真源精度。
- 若真源无法满足既有 ADR，只交付尺度差异和边界敏感性证据及可支持用途，保持正式资格阻塞；需要改变分析粒度或目标时走 ADR 评审，不在本规格中自动批准替代方案。
- 区分三个几何对象：以分析点和公里半径定义的地理圆、地图 bbox 视野、距离真实锋线的缓冲/距离带。支持判断包含完整请求几何；只有部分可覆盖时明确裁剪后的有效支持，不能悄悄换圆或换中心。
- 地理距离/面积方法、坐标系、数值容差和边界包含规则版本化。经纬度格面积随纬度计算，海域分母不包含陆地和无效/未知覆盖；不能以度数面积直接冒充平方公里。
- 格心归属或交叠面积分摊根据源语义、可实现精度和小例比较后冻结。分摊说明格内均匀假设，并与格心方案核对敏感性；不声称知道格内实际船舶位置。P0 输出可复算几何小例，正式月统计直接参照仍属 A。
- 重叠缓冲采用并集或互斥规则避免重复计时，嵌套半径分别核对而非相加。邻近多锋面/无法判定侧别保留不确定状态，不以每日 F 编号假定跨日事件身份。
- 指标合同区分区域总小时、固定支持上的日均和面积时间密度。面积时间分母为逐日有效面积乘有效时长的累积，单位平方公里·日；小时分子必须来自同一共同支持。
- 有效分母为零或未知时输出不可计算与原因，不返回零密度。活动基线为零时相对变化率不可直接计算；保留绝对变化和基线状态，不添加隐式伪计数或输出无穷大。
- 现有 10/20/30km 只作为已存在 UI 档位登记；每个研究用途的支持取决于实际粒度、区域边界和质量，不自动批准新档位。半径/阈值的例行实验结果在合同中冻结；涉及研究目标变化时再交评审。

### 6. 分析条件与支持判定接口

- 建立供审计、现有确定性查询及后续 A/B/C 共用的条件合同：任务/用途、分析点或固定区域身份、公里半径/几何、日期/月及窗口、必需图层、源版本、处理/方法/参数版本、质量规则和单位。
- 支持判定至少返回：原请求身份、所需日期和几何、各层及共同支持、小时分子/有效分母可否使用、支持等级、原因列表、证据引用、缺失前置、合同版本和审计时间。未知数字使用明确未知表达，不用默认零代替。
- 区分“支持”“有限支持”“暂不支持”“未核实”，并按用途作判定。有限支持只能开放其证据覆盖的描述/显示用途；不能用总状态良好绕过正式研究的阻塞。静态支持判定不触发归档准备、重分析或下载。
- 正规化仅作用于语义等价输入，不偷偷改变日期、半径和空间范围；拒绝非法条件，并在允许的轻量降级中明确返回实际使用条件。缓存和结果不能跨资料/方法版本误复用。
- 优先复用现有清单、索引、可用性和确定性查询入口，以同一审计快照补充可选的支持/证据摘要。保留旧调用方兼容，旧 ready/available 字段只保留其既有文件级含义，不能单独解释为 research-ready；无需另建 AI 入口或为审计建立第二套统计引擎。
- 重量检查显式执行并生成快照；普通清单/支持读取使用已经完成且身份匹配的轻量产物。快照过期或扫描中说明范围和新鲜度，不因访问网页隐式扫描多年原档。
- 维护者原始文件定位与公开支持摘要分开；公开摘要不包含服务器地址、个人绝对路径、凭据或可逆细网格。只投影已确认可公开的内容，记录来源和局限；新重扫描能力不开放为访客重任务。

### 7. 交付物与阶段关口

| 交付物 | 必须能核验的内容 |
| --- | --- |
| 来源与身份登记 | 产品/角色、单位、粒度、来源到产物、版本证据和许可冲突 |
| 全日历覆盖台账 | 每层每日声明/实际读取/语义/支持状态、联合支持、排除与未核实原因 |
| 条件与几何合同 | 点/圆/bbox/缓冲区分、时间窗口、边界/面积规则、用途和版本 |
| 支持判定结果 | 东海2024-08候选及代表位置/半径的等级、分母证据、理由与后续前置 |
| 可复算小例 | 正常、零、未知、边界、重复/冲突、窗口不足的输入/预期/输出及容差 |
| 审计报告与差异 | 历史基线对比、本地/离线/服务器一致性或未知点、实际检查及复算说明 |

- P0 审计能力完成与 GD 研究资料关口通过分别记录：发现没有合格月份是有效审计结论，但不是 A 的研究前置已解除。若只有本地部分完成，#14 继续登记线上/源资料缺项，不凭一份报告关闭工作包。
- GD 对目标用途通过时，需要共同有效支持、许可/访问、源粒度或已批准替代、几何/分母规则和复算参照均满足；不存在默认“清单31日即通过”。阈值及容差在来源/小例检查后冻结，有版本和依据。
- 真源或服务器不可访问时，先做合法可读部分和合成合同检查，列具体缺口与解除条件。无需虚构服务器事实，也不阻止界面/P1 可独立进行的工作。
- 本规格不预定最终通过月份、有效面积、半径上限或误差阈值，不要求正向或显著锋面关系。参数调整记录新版本、原因和影响，不为凑通过修改质量标准。

## Testing Decisions

### 1. 已确认的主要验证入口

以“显式执行一次数据审计，获得版本化报告和条件支持判定”为主要端到端入口。复用现有本地审计/清单的批处理入口，将合法小样本送入真实读取、解码、几何、状态判定和输出链，核对可观察产物；正常读取与确定性查询只做同一快照的消费回归。

已有 API 合同检查使用 FastAPI 测试客户端验证清单、有效性摘要、部分/空态及缺资料不等于零；已有数据检查核对源/导出一致性。无需新增测试专用业务接口，也不把浏览器外观作为本数据合同的主要验收入口。复杂几何小例可在公共审计入口输出中核对，避免大量只镜像内部函数的测试。

用户已于 2026-10-24 确认“按上述边界验收并发布（推荐）”：审计报告与支持判定为主，手工可核对小例验证语义，现有 API 验证同源消费，真实资料审计和合成测试分别记证。此前界面浏览器验收决定继续有效。

### 2. 好的测试与已有基础

- 检查外部输入、报告、资格理由、API投影和可复算数字，避免绑定内部函数拆分、目录布局、字段排列或仅为实现而写的断言。
- 现有本地审计已有文件日期一致性和完整日历检查；现有清单/索引可提供日期配对；既有 API 测试覆盖缺资料、部分支持、空态、版本缓存与缺数据不报零。扩展这些入口，使文件级和研究级资格分清。
- 使用少量明确标注的合成 NetCDF/活动夹具控制边界、单位和状态，独立手算/可信直接参照验证分子分母；不让同一被测聚合函数生成期望值。
- 真实资料审计与合成合同验证分开记录。合成全月通过只说明规则实现正确，不能证明东海实际全月有效；网络受控响应只证明错误合同，不证明实际源覆盖。

### 3. 必须覆盖的场景

| 场景 | 预期外部行为与证据 |
| --- | --- |
| 文件清单完整但某日坏文件 | 全日历保留该日失败，不记有效覆盖或补零 |
| 单层缺日/时间错配/多日文件 | 识别实际日期和必需层联合支持，展示排除理由 |
| 显式0、缺字段、null与稀疏无记录 | 分开保留；仅有充分语义证据才能解释未出现格为零 |
| 清单默认粒度/bbox/小时与源不符 | 标记缺省来源和冲突，不能据其解除研究阻塞 |
| 单位/填充值/缩放及异常数 | 正确规范化并保留来源；未知单位或非有限/负小时有原因 |
| 重复日/格、冲突版本和聚合 | 不双计，冲突未解不通过；守恒核对及容差有记录 |
| 海岸/跨覆盖边界公里圆 | 区分请求、有效与未知面积，bbox不替代圆，陆地不入海域分母 |
| 不同纬度、边界格与重叠缓冲 | 面积/距离有独立参照，归属一致，重叠不重复计时 |
| 有效分母0/未知、零基线 | 不输出假零密度、无穷大或伪精确相对增幅 |
| 月初月末前后窗口不足 | A和B资格分别判断，缺邻月不推算后7日 |
| 显示可用但精度/覆盖不足 | 可以限定显示，正式研究资格仍阻塞并附原因 |
| 同输入重跑、源变化与过期缓存 | 实质结果稳定；内容/方法变化有新身份，不串用旧资格 |
| 不可访问、未准备、权限或临时失败 | 状态可区分，报告未知项；查询不自动准备或下载 |
| 公共摘要与维护者定位 | 公开投影不泄露私人路径、原始资料和受限格网 |

### 4. 真实验收和证据记录

- 实施阶段逐日核实首选候选月，并记录对必需层及相邻窗口实际执行的检查和未核实项。许可允许的聚合摘要可保存，受限源资料和细网格不进入 Git 或公开 Issue。
- 每次运行记录输入/资料身份、程序与合同版本、参数/几何规则、检查范围、生成时间、失败和缺口、结果与数值容差。报告摘要与支持判定、API消费保持同源；仅对受影响接口运行回归，后端合并前完成仓库要求检查。
- 此轮仅整理规格，未重跑真实数据审计、后端测试或线上逐日读取。文档只做结构、链接与敏感信息检查，不填写虚构通过数、研究就绪状态或部署结论。

## Out of Scope

- 正式完整月 A、B 事件/对照及分组推断、C 区域比较的科学计算与结论；仅输出它们的输入资格、几何/分母合同及小例。
- 预测训练与独立回测、在线模型或 AI 工具执行、完整任务中心与报告产品化。
- 界面两侧布局、图表美术、换日请求竞态实现；继续由 #25–#34 等既有任务承接，不重复建单。
- 论文性能方案实验、服务器容量/采购结论、完整归档迁移、扩大原始数据下载范围和高并发压测。
- 未获批准的 ADR 粒度变更、新半径科学支持、无依据的覆盖门槛，以及把展示插值视为新观测。
- 自动准备/获取不可访问资料、购买授权、合并或部署，扩大受限数据公开范围。
