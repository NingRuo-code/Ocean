# Ocean G3 相似案例检索与短窗口辅助匹配实施规格

整理日期：2026-10-24。来源：总体规划G3/T、Q32及领域相似事件定义，承接P0、A/B/C、W和已发布G3独立复核规格#141。状态：已发布 [规格 #159](https://github.com/NingRuo-code/Ocean/issues/159)，标签 `ready-for-agent`；验证边界已获用户确认。本轮未实施检索、匹配或取得新实证。发布标题：`[Spec] G3 相似案例与辅助匹配：可解释检索、响应对照与断档说明`。

执行任务已按用户确认发布为#160–#175：[16项任务与阻塞关系](../tickets/g3-similar-case-and-auxiliary-matching/README.md)。本行仅为本地导航，远端规格正文保持不变。

## Problem Statement

使用者看到某片海域、某个日期的锋面和活动后，希望快速找到过去环境相近的情形，查看当时活动怎样变化、哪些情况不相同，以判断历史证据是否值得参考。翻找历史图、只看增强案例或依赖不透明分值，都容易误读系统的渔业参考价值。

当前已有按日对象提取、历史查询和质心/长度像元规模/包围框的短窗口启发式匹配。它们尚未构成可解释的相似案例检索：对象编号依赖日期与提取范围，长度和像元数是尺度相关的近似；追踪遇到缺日或重新锚定后也缺少足够的连续性约束。锚定分数和匹配分数不能被解释为身份概率，更不能替代固定区域B事件定义。

需要把“历史情形相似”“相邻日期可能关联”“真实事件及其响应”和“独立研究验证”分清。相似案例帮助理解证据，不等于预测、因果或成功率；新检索还可能揭示原本保留的验证资料，必须尊重G3独立复核的数据接触边界。

## Solution

在既有工作台提供按需的“相似历史案例”入口，沿用已应用的点位、公里范围和参考日期，或引用选中的固定区域事件。默认先在同海域、版本明确的季节窗口内检索合法且已就绪的历史候选，再按有依据的环境和事前活动特征解释相似程度。显示实际检索库范围、采用特征及缺项，不静默扩大海域、改半径或扫描全部归档。

先返回少量简短候选，展开后并列原A/B证据、窗口/支持、差异和失败情形；地图只在明确选中/定位时联动，保留原地图框架和非模态操作。结果选择依据与后续活动响应分离，反向、无明显变化、无响应资料和无法比较的案例也可出现。没有可比结果时明确限制，不生成新评分、联合推断或预测。

需要核对相邻日期对象时，复用现有短窗口匹配，显示候选、距离和形态代理依据、歧义、缺日与重新锚定。缺口两侧不画成已经确认的连续锋面，不为检索建设深入移动、分裂合并或生命周期模型。提供版本化检索结果和合法聚合阅读证据，后续报告、AI和预测可以按各自规格消费。

## User Stories

1. 作为使用者，我希望从工作台呼出相似历史案例，以便不必在右侧常驻大量分析内容。
2. 作为使用者，我希望沿用已应用的位置、公里范围和参考日期，以便减少重复填写。
3. 作为使用者，我希望也能从已选固定区域事件发起检索，以便寻找相似响应背景。
4. 作为使用者，我希望明确看到当前检索条件，以便不会把筛选草稿或旧结果当成当前请求。
5. 作为使用者，我希望默认先检索同海域与相近季节，以便案例具有基本可解释性。
6. 作为使用者，我希望知道季节窗口、年份和候选库覆盖，以便了解检索范围。
7. 作为使用者，我希望跨年和闰日的季节匹配有明确规则，以便日期边界不会漏选或错选。
8. 作为使用者，我希望扩展条件由我明确操作，以便系统不会悄悄换海域或扩大范围。
9. 作为使用者，我希望结果说明相似在哪里、不同在哪里，以便理解每个参考案例。
10. 作为使用者，我希望缺少特征时明确显示，以便不把未知温度或活动当成零差异。
11. 作为使用者，我希望候选选择不依赖后续响应是否增强，以便不会只看到支持结论的案例。
12. 作为使用者，我希望按事前活动检索时看到实际时间窗和支持，以便不误用未来信息。
13. 作为使用者，我希望不使用的形态或强度特征不会被编造，以便结果忠实于实际数据。
14. 作为使用者，我希望有确定的检索顺序和并列规则，以便同条件可以复查。
15. 作为使用者，我希望检索相似顺序不被当作渔场优劣排名，以便理解其用途。
16. 作为使用者，我希望先看到少量候选再按需展开，以便界面保持简洁。
17. 作为使用者，我希望翻页仍属于同一候选库版本，以便不会漏掉或重复案例。
18. 作为使用者，我希望看到无明显变化、反向及失败案例，以便了解历史参考的局限。
19. 作为使用者，我希望缺少活动响应的环境案例仍有准确状态，以便不把无资料当无响应。
20. 作为使用者，我希望展开案例读取原结果及来源，以便不用重新计算就能核对。
21. 作为使用者，我希望A月度背景与B事件响应分别显示，以便不混淆研究单位。
22. 作为使用者，我希望B前7日、当日、后1–3日与真实后1–7日分别显示，以便正确理解变化。
23. 作为使用者，我希望小时、面积时间、密度和区间保持原单位，以便比较有明确含义。
24. 作为使用者，我希望条件不兼容时仍看见原因，以便不会被强行生成差值或判断。
25. 作为使用者，我希望重复事件及相关样本明确关联，以便不把多个版本或半径当独立证据。
26. 作为使用者，我希望历史截点之后才出现的资料有提示，以便不把后见信息当当时可知。
27. 作为研究者，我希望保留检索和目标资料接触记录，以便不会污染未见验证却不知情。
28. 作为研究者，我希望受保护的验证资料默认不进入检索，以便方法选择与最终复核隔离。
29. 作为研究者，我希望没有验证登记服务时明确独立性状态，以便不会凭空声称独立。
30. 作为使用者，我希望点击历史候选后再定位地图，以便日期和图层不会突然改变。
31. 作为使用者，我希望查看案例时地图仍可拖缩和选点，以便探索过程连续。
32. 作为使用者，我希望改筛选后旧检索保留原条件并标待更新，以便不会因连续修改重复计算。
33. 作为使用者，我希望必要时查看短窗口的候选对象关系，以便核对事件附近的观测。
34. 作为使用者，我希望看到匹配距离、形态代理和歧义，以便不会只信一个分数。
35. 作为使用者，我希望缺日、无对象和重新锚定分别显示，以便不会误认连续身份。
36. 作为使用者，我希望断档处不画误导连线，以便地图忠实反映已知关系。
37. 作为使用者，我希望锚定和启发式匹配不显示身份概率，以便不被百分比误导。
38. 作为研究者，我希望对象提取范围与版本可追溯，以便编号重排或裁切变化不会制造错误身份。
39. 作为研究者，我希望短窗口关联不改变B固定区域事件，以便匹配不确定不会重写科学结果。
40. 作为维护者，我希望索引只包含合法且必要的摘要，以便检索不会暴露细粒度AIS和私人案例。
41. 作为维护者，我希望权限检查覆盖搜索、计数、详情和直接引用，以便私人来源不会泄露。
42. 作为维护者，我希望只读检索不自动准备归档或分析，以便查询成本和使用权限可控。
43. 作为维护者，我希望候选库或方法更新产生新身份，以便旧检索仍能按原版本理解。
44. 作为维护者，我希望中断、部分失败和空结果准确区分，以便不会出现假成功。
45. 作为维护者，我希望有界索引与普通精确筛选基线，以便只在真实瓶颈出现后增加加速方案。
46. 作为负责人，我希望真实检索、真实匹配核查与合成边界分开记证，以便准确跟进进度。
47. 作为负责人，我希望没有相似案例也能诚实验收软件行为，以便不强求正向研究结果。
48. 作为后续集成者，我希望得到稳定的结果引用和合法聚合证据，以便报告和AI消费同一结果。
49. 作为使用者，我希望手机能完成基本检索和阅读，以便基本功能不会依赖大屏。
50. 作为研究者，我希望相似检索不被当作独立验证或预测增益，以便保持结论边界。

## Implementation Decisions

### I01 范围和已有基础

- [ ] 归属总体规划G3/T及#13，复用P0#35、A#60、B#72、C#85、W#95和G3独立复核#141；相似检索与独立复核是不同成果，不修改或关闭已有父级/任务。
- [ ] 现有对象/追踪接口是可复用基础，质心、长度/像元规模与bbox是启发式依据；当前存在锚定、缺日及重置语义不足，不能据接口存在宣称匹配质量已通过。
- [ ] 首版核心为同海域季节检索、逐特征差异、原A/B响应阅读和必要短窗口核对；不新建完整追踪、事件、数值统计或预测引擎。
- [ ] 环境案例、固定区域B事件、A月度背景、REPORT个人保存案例分别保留类型和身份；主参考对象为历史情形及其可用B响应，A只作独立背景，不将不同单位混池排序。

### I02 请求和历史候选范围

- [ ] 请求继承已应用点位、公里圆和参考日期，或精确引用原B事件/结果，保留检索类型、范围/年份、海域定义、特征配置及候选库版本；草稿修改不改变旧结果。
- [ ] 同海域先用有版本且可审计的范围定义；无法确定时要求明确研究范围或返回不支持，不从文本名称猜测，也不将视野bbox等同公里圆。
- [ ] 沿领域既有同海域、前后15天季节窗口作为首轮透明检索基线，参考日/锚日、跨年环绕、端点包含、闰日和实际候选日期规则登记并用手工日历核对；不将15天说成已验证的生态最优阈值。
- [ ] 默认候选锚日早于参考日期，查询自己的同一事件/同一结果及其重复版本须识别；范围、半径或季节窗口扩展是明确新请求，不自动放宽到外海域或全部年份。
- [ ] 所谓无案例只对当前合法且已索引候选库成立。返回库覆盖、实际读取范围、分页状态和未准备/未知范围，不宣称全部历史没有相似情形。

### I03 候选目录与资料支持

- [ ] 建立最小研究候选目录，引用P0资格、已就绪对象/环境摘要和已有A/B阅读包；不复制REPORT个人案例数据库，不将标题/标签搜索等同环境相似检索。
- [ ] 目录逐项记录候选类型、固定几何/实际提取范围、日期/事件锚日、海域、源/处理/方法版本、特征/单位/支持、结果引用及许可。必要新特征仅经显式受控加工生成，不在普通搜索中扫描原档。
- [ ] 对front/SST/活动按实际特征用途核共同支持，保持P0粒度、有效零、缺测和版本合同；只有锋面/SST的候选可提供环境参考，但响应栏明确无资料，不把无记录当零响应。
- [ ] 未准备归档、未索引、缺测、解析失败、无事件、无法计算特征和原结果不可得分别表达；已保存索引不自动证明当前研究资格或允许公开。
- [ ] 基础目录可先用合法已知摘要开发，真实B响应消费依#84；不把G3全部跨年/外海域任务或完整REPORT完成作为基础检索统一前置。

### I04 特征与选择偏差

- [ ] 基础硬筛选为海域、季节、可用性和已声明研究范围；可选特征从实际有据的SST、最近锋面关系/可判定侧别及事前活动中选择，逐项登记定义、支持、单位和时间窗。
- [ ] 不用后1–3/后1–7响应、增强标志、最终效应或显著性筛选/排序；原对照匹配与G3检索不同，检索候选不自动成为B合格对照或独立验证样本。
- [ ] 事前活动须声明截止日期及前期窗口、H/E与覆盖，禁止用整个目标月或含未来响应的汇总冒充事前特征；环境/活动同支持与不同支持明确标注。
- [ ] 缺特征不是零，也不是最相似。必需特征缺失不进入该检索配置；可选特征缺失单列信息不足候选，不能与完整特征候选按不同维数分数直接混排。
- [ ] 长度/像元数、方向、形态和强度仅在实际字段/代理定义与尺度可比时启用；温差/梯度不冒称原始锋面强度，当前长度估计不作为精确形态真值。

### I05 可解释顺序和完整候选

- [ ] 先实现有界候选集上的普通精确筛选与逐特征差异，形成正确性基线；无需强制向量库、学习排序、嵌入或自创相似算法。
- [ ] 首版以固定、可解释的特征差异顺序和稳定候选身份处理并列；若采用综合距离，尺度/权重/缺项规则在探索样例定下后版本化，明确它是检索度量而非身份概率或作业分数。
- [ ] 返回采用/未采用特征、原值、差异、缺项及纳入/排除依据；界面主展示短理由和关键差别，详细配置按需展开，不堆砌评分规则。
- [ ] 返回数量有界、支持稳定分页，游标绑定查询及候选库/索引版本；版本变化明确重新检索，不跨版本漏项/重项或把截断返回量当全库总量。
- [ ] 候选选择先于响应内容读取，保留选中清单及顺序依据；真实回放核正向、反向、无明显变化和无响应资料不会因结果方向被排除，必要时以合成反例验证而不要求真实一定出现各方向。

### I06 历史截点和验证资料接触

- [ ] 默认明确为历史研究参考，不声称实时作业或预测；参考日期、观测日期、候选锚日、结果窗结束日和资料可知性分别表达。
- [ ] 候选后续响应窗跨越参考截点或首次可用时间无法核实，不能标为当时可知；需要回顾性查看时明确后见/未知可知时间，不能静默用于当时参考或预测评价。
- [ ] 消费#141/#144已有分区/接触合同，受保护最终复核资料默认排除出可检索内容及响应详情；跨层相关组按#145已登记关系处理，不靠改候选ID绕过保护。
- [ ] 若隔离服务/记录尚未接入，检索只能运行在明确的探索/公开样例允许库，不对任意未登记资料默认放行并声称独立；这不要求整个G3实证关口关闭才能做开发。
- [ ] 检索、详情和图示一旦向研究者揭示目标关系，记录实际资料/结果、范围、用途与时间，按原冻结流程更新接触状态；不自动释放保留集、重标独立或替用户选择新验证集。

### I07 同源响应阅读与重复样本

- [ ] 展开案例读取原A/B合法阅读包及精确结果版本，不自动运行A/B或补缺窗口；A月度背景与B事件响应分板，固定几何、实际日期和观测对象分别可查。
- [ ] B保留原事件锚日/成员/相关组、前7/当日/后1–3/真实后1–7、H/E、对照、效应/区间及降级，不从相似距离或匹配分数生成响应数值。
- [ ] 复用C已有兼容规则逐项说明单位、窗口、半径、源/方法和支持是否可比；可并列原值，已有合法差值保留来源，缺兼容计算不现场制造新统计差值、区间或检验。
- [ ] 同一事件的不同半径、版本、重复保存案例和相邻相关事件保持关系，列表按协议去重/分组并可查变体；候选条数、事件数和独立组数不混称样本量，不把近邻案例平均成成功率。
- [ ] 原结果缺失/权限变化或支持不明时保留允许的状态说明，不用当前新结果冒名覆盖；无变化、反向、未知和不可比均正常呈现，不输出渔场推荐排名、鱼量、渔获或因果结论。

### I08 短窗口辅助匹配输入与度量

- [ ] 必要时沿既有对象/追踪受控入口查看短窗，从当前默认3日小窗起步；实际支持上限依可访问资料和预算验证，不默认全月/多年重建轨迹。
- [ ] 请求绑定观测日、固定公里范围、实际读取/提取范围和算法/源版本；旧角度范围接口仅作兼容适配，沿P0公里几何核实际支持，不能将角度数值直接改名公里。
- [ ] 对象引用至少绑定日期、源/处理、提取范围/裁切和方法，再引用局部F编号；裁切和分辨率改变可能改变组件、长度和编号，不声明全海域或跨日永久身份。
- [ ] 复用已有质心距离、长度/像元规模代理、bbox重叠计算结构，保留各项依据和候选数/备选差异；度量适用尺度、边界和阈值根据合法小例及真实核对记录版本，不照搬现有权重为已验证最优方案。
- [ ] 原锚定分数1只是初始化状态，不显示100%身份把握；bbox/像元相似和总分都不是校准概率。无依据时允许只给距离与可疑关联，不强行评为可靠连续锋面。

### I09 歧义、断档与固定区域事件边界

- [ ] 区分初始锚定、可能关联、歧义、无合格候选、无对象、缺观测、读取失败和重新锚定，结构化状态与简短文字一致；多个候选难以区分时保留备选，不只画一个确定答案。
- [ ] 缺日、无对象或失败后不携带上一个对象冒充相邻日连续；新的段与原段分开，跨缺口恢复仅标待核对，不自动长期身份恢复。
- [ ] 超出门槛/无法可靠关联而回到查询点锚定时，建立新段并显示重置；地图不跨断档或重置画连续轨迹，不将重置前后距离累加成同一锋面的迁移量。
- [ ] 弱匹配/歧义线仅在明确图例下按候选关系显示，空值/旧哨兵值不当真实0距离或0温度；几何裁切、分辨率与代理局限随详情保留。
- [ ] 辅助关系不重写B#74按固定区观测定义的事件/锚日/组，不因为每日F变化拆事件，也不因短窗关联强而合并B事件；人工核对标注与原确定性结果分开。

### I10 易用界面与地图协调

- [ ] 复用W引导入口和现有结果/底部详情，工作台按键呼出检索，筛选仍沿统一条件模块；左侧不新增第三组常驻长卡，右侧只保留简短状态/结果入口。
- [ ] 桌面默认少量候选与简短相似/差异理由，展开后看原证据及匹配详情；手机支持基本发起、分页、展开和返回，完整复杂多案例工作流不作为小屏首批承诺。
- [ ] 地图保持原框架、非模态拖缩/选点/图层操作；检索返回和展开详情不自动更换日期/视角，用户明确选择定位时才按该候选真实日期/固定区或短窗观测上下文联动。
- [ ] 修改条件后旧结果保留原条件并提示待更新，明确点击再检索；乱序响应按请求/库版本隔离，加载、部分失败、无候选、无响应资料和权限限制各有可读状态。
- [ ] 不将候选相似顺序设计成作业榜单，不常驻详细分值/权重/长规则；沿已确认两侧区分及工业视觉风格做最小接入，不另行重画地图、色标或推翻布局。

### I11 权限、版本和查询成本

- [ ] 服务端在候选过滤前核公开就绪范围或本人授权，搜索计数、分页游标、摘要、详情和直接ID读取均不泄露私人案例/源；可读研究结果不自动获得保存/对外导出权。
- [ ] 索引只收实际允许的必要聚合/元信息，来源路径、受限细网格和可重建AIS不进入公开索引或证据；逐源许可及署名沿P0/REPORT合同核对，个人笔记不作为公开相似特征。
- [ ] 身份覆盖请求、候选库/索引内容、源/特征/检索/匹配方法、分区/接触策略及原结果引用，重复只读可复用，更新产生可区别结果；生成时间不伪装新源版本。
- [ ] 候选/索引更新原子可见，失败/半写不冒称完整库，旧结果保留原条件及过期/可复算状态；资料清理后只读旧证据与可重新匹配分开，遵守TASK保存保护合同。
- [ ] 搜索/分页/展开只读就绪摘要与结果，索引构建/特征加工及新的短窗源计算走本人显式有界执行；限制返回量、并发、扫描/内存和缓存，按实测登记耗时/规模，不新定未经验证的秒数或采购配置。

### I12 真实核查与交接

- [ ] 真正贯通浏览器操作→实际检索服务/受控计算→候选/原证据/地图详情，不能用静态卡片、假任务或旧报告拼文案冒充已实现。
- [ ] 真实合法历史候选至少形成一个可重放的查询及不同真实案例的逐项阅读，包含可核对B响应才声明响应检索完成；仅环境资料只验环境范围，不以复制案例或合成候选补真实数量。
- [ ] 短窗匹配在可访问真实连续观测上实际运行并独立逐日图示核查，记录可能关联、歧义、边界及不能判身份；缺日/重置等不足的真实情形可用明确合成反例补软件边界，不冒充真实发生。
- [ ] 以固定候选集核普通海域/季节基线及可选特征是否按定义选取，响应方向变换不改变选择；真实人工核对记录依据和不确定，不把主观偏好当物理身份真值或宣称已校准准确率。
- [ ] 交接检索条件/库版本、选中清单、接触记录、原结果/短窗段引用、合法聚合图表和限制；REPORT新增类型/保存导出适配、完整AI与预测另行验收，G3#158独立复核成果不自动成为检索必须先完成的关口。

## Testing Decisions

主接缝采用真实浏览器中的“相似历史案例/辅助核对”操作，经现有API或同一受控计算服务，读取实际候选及原A/B证据，并联动已有地图/详情。辅助API、独立手工小例和产物检查核对该链路，不新建测试专用业务入口；短窗计算复用现有对象/追踪服务。

1. **检索外部行为**：从已应用条件发起、分页、展开、明确定位、改条件待更新与重试，核实际候选库/请求身份、原数据/证据及地图日期一致；地图始终可操作，右侧保持精简。桌面为完整流程，手机核基本阅读。
2. **独立已知候选集**：手工列出同海域/窗口边界、跨年/闰日、重复事件/版本、零/缺特征及并列候选，核精确纳入/排除、特征差异、稳定顺序/分页和全集范围；不复制实现作为期望生成器。
3. **防选择偏差与后见信息**：只改变后续响应方向而保持检索特征，选择及顺序不应改变；核事前活动窗、参考截点之后响应、未知可知时间、保留集阻止与接触登记。服务未接入时只允许明确探索库，不伪称隔离成功。
4. **原结果兼容阅读**：核A/B分板、B各窗、H/E及单位、有效零/缺测、无事件、区间不足、相同事件多半径与不可比状态；原结果不可得/权限撤销不自动重算或替换。已有C差值沿原身份读，没有则并列并说明。
5. **短窗独立小例**：用可手算几何和独立逐日对象序列检查锚定、多个备选/歧义、超过门槛、缺文件、无对象、失败/重置及裁切/编号变化；核断档后分段、无误导连线/累计迁移、匹配分值不当概率、B事件不被改写。
6. **真实证据分账**：真实历史检索/不同案例及真实B响应消费、真实短窗逐日核查分别留证；合成边界、环境可用、响应可用、独立性和实证验证分别登记。没有好案例或正向响应不使正确软件失败，但真实资料不足保持对应关口未完成。
7. **服务与状态**：实际核搜索/计数/分页/直接引用的本人/访客边界、索引半写/更新、迟到响应、中断、缓存版本和普通读取不重算；资源实验在合法有界库执行，不重复P1全面压测或TASK恢复平台。
8. **沿用现有基础**：复用对象/追踪API已知小例、P0支持/版本、A/B同源阅读、C兼容判定、W非模态/原条件定位和G3接触/分区检查；补检索与断档新行为，不将现有单对象初始化断言当真实匹配质量验收。

## Out of Scope

- 不重做P0审计、A/B数值引擎、C正式比较、W框架、REPORT个人案例管理或G3独立复核；只按实际接缝适配复用，不等待全部模块或全部实证任务完成。
- 不以相似排序给出作业排名、把握度、成功率、渔获、收益或因果结论；不把检索样本平均响应当独立研究或经过验证的预测。
- 不实现深入锋面移动规律、长期身份恢复、分裂合并、生命周期或完整轨迹标注平台；不扩展为全海域对象长期追踪。
- 不强制向量数据库、学习排序、嵌入/大模型相似计算、复杂形态网络或新数学算法；仅真实瓶颈/基线不足有证据后另设必要实验。
- 不生成新跨区显著性、自动重算A/B/C、自动准备归档/放宽范围、购买数据、扩容或部署；现有统计结果之外的研究计算由对应明确任务承担。
- 不交付系统内新增类型的完整PDF/PNG/CSV成果包、公共分享链接、完整AI对话或活动预测回测；提供同源合法阅读证据和交接合同，相关适配另行验收。

## Further Notes

这份规格补齐G3中“相似案例与辅助匹配”部分；#141及#142–#158承担独立复核。二者共享数据资格、版本、相关组和接触台账，但不能互为全部任务的前置。检索揭示目标关系会影响后续独立性，记录真实接触比给结果标一个“未见”标签更重要。

实际前置按能力分开：P0#41/#43提供资格和版本；B#74提供固定区事件，#84交接真实窗口/响应；A#71用于已有月度背景，C#87兼容判定可复用而不强制等待完整#94；W#107原条件定位/地图共存用于薄界面集成。#144/#145提供正式保留集隔离时的接触与相关分区，未具备时限明确探索库。REPORT#127/#128负责个人保存版本与标题检索，本规格不再建设第二份个人案例系统。

已有对象提取依查询子集计算组件及局部编号，短窗匹配使用质心、尺度相关代理和bbox；本规格要求修正断档/重置的展示及语义，而不要求从零建设追踪算法。旧报告将匹配值按百分数表达的做法不能直接复用于身份把握度。

领域旧说明里的固定增强阈值、远距离对照和产品评分不作为本规格数值规则；后续正式A/B/C与已确认精简界面合同优先。季节窗口沿用既有透明基线，其日期规则、特征支持和必要门槛由合法小例/实际资料核对后版本化，不依据最终响应调参；粒度或核心定义变化依既有ADR流程处理。

本轮只整理规格。软件实现、真实检索、实际响应消费、短窗质量核查、独立验证、PR、合并和部署分别记证；数据不足不能靠合成测试或任务关闭消除。
