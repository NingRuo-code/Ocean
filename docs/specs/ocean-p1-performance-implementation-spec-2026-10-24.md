# Ocean P1 性能基线、可视化加速与容量评估实施规格

整理日期：2026-10-24。关联既有性能工作包 #17 和执行总纲 #13；承接 PERF-01–08，按前置分批推进。用户已确认验证边界，已发布：[规格 Issue #45](https://github.com/NingRuo-code/Ocean/issues/45)，标签 `ready-for-agent`。发布标题：`[Spec] P1 性能基线与瓶颈优化：地图加载、算法对照和服务器容量`。

实施任务已按用户确认发布为#46–#59：[任务与阻塞关系](../tickets/p1-performance/README.md)。本行仅为本地交付导航，不修改远端父规格正文。

## Problem Statement

使用者需要顺畅地打开地图、切换日期、拖缩海域并理解锋面与 AIS 表观捕捞活动的位置关系。当前系统已有 LOD、缓存、窗口取数和栅格接口，但没有统一证据说明时间主要消耗在哪里、既有优化是否有效、完整研究工作集需要多少服务器资源。

现有静态文件、一个活动日响应及历史机器注释，不能回答完整月或多年数据的加载速度与容量。旧活动层分位过滤和700点截断还会使少画数据的页面看似更快；请求成功、底图出现或接口耗时也不等于当前观测已经可用。没有同条件、同语义基线，直接换框架、扩大缓存或买服务器都难以判断收益。

需要先复现用户操作、定位各阶段成本，再按瓶颈改进请求、缓存、显示聚合和绘制；论文及数据格式方案进入有前置、有普通参照的实验。速度改善必须保持资料身份、数值含义和原地图操作，同时给出有事实依据的容量与部署限制。

## Solution

建立一套围绕真实浏览器操作的端到端测量流程，关联实际请求与服务端诊断，输出固定场景的冷热耗时、成功/失败、字节、绘制、长任务和资源报告。首先区分不可用、身份错误与速度慢，再对同版本资料及同语义负载逐项优化。

近期优先概览后明细、当前请求优先、在途复用、有界跨日缓存、图层增量更新、隐藏面板按需计算，以及活动远景聚合和近景完整显示。优化可独立回归，保留原地图框架、查询能力、科学图例和完整分析真源。

PNG、COG、Zarr、Mosaic Selections 等只在对应瓶颈与资料合同具备时进入小样对照；结果可以是采用、限定采用、延后或放弃。最后以实测工作集与受控负载，回答现服是否可保留、瓶颈需要何种资源、哪些规模仍未验证。采购、全档迁移和部署另行处理。

## User Stories

1. 作为地图使用者，我希望首开尽快得到可读且可操作的真实概览，以便开始探索海域。
2. 作为使用者，我希望切日期保留视角和缩放，以便比较同一位置的变化。
3. 作为使用者，我希望新日期未就绪时不出现旧图配新日期，以便不读错资料。
4. 作为使用者，我希望拖缩后尽快补齐当前视野明细，以便查看局部关系。
5. 作为使用者，我希望概览与明细精度有清楚区别，以便不会误认为已经看到全部细节。
6. 作为使用者，我希望加载期间仍能操作地图，以便探索不被工作台或计算阻断。
7. 作为使用者，我希望快速连续操作时优先处理最后条件，以便旧请求不拖慢当前任务。
8. 作为使用者，我希望相同条件的重复请求被复用，以便减少无效等待和流量。
9. 作为使用者，我希望相邻就绪日期能适度预取，以便连续查看更顺畅。
10. 作为使用者，我希望预取不会挤占当前请求或启动归档加工，以便操作可控。
11. 作为使用者，我希望连续播放后内存仍受控，以便长时间使用不会越来越卡。
12. 作为使用者，我希望缓存命中不会返回别的日期或版本，以便更快仍然可信。
13. 作为使用者，我希望只改变必要图层，以便切换功能不反复重建整幅地图。
14. 作为使用者，我希望收起的复杂面板按需计算，以便地图交互优先。
15. 作为使用者，我希望远景汇总活动仍保留小时总量及下钻能力，以便不会遗漏结构。
16. 作为使用者，我希望近景看到视野内完整有效活动格，以便不受默认热点截断误导。
17. 作为研究者，我希望分析始终读取完整有效输入，以便地图聚合不改变科学结论。
18. 作为使用者，我希望图像加速后仍可查点、选择锋面和读图例，以便常用功能保留。
19. 作为研究者，我希望图像颜色与查询数值来自同一色标及资料版本，以便不会图数不一致。
20. 作为维护者，我希望区分实际浏览器请求和本地实现，以便先修复部署或路由差异。
21. 作为维护者，我希望将服务读算、传输、解析和绘制分开测量，以便针对最大成本改进。
22. 作为项目负责人，我希望看到冷启动和热缓存的分布，以便不被最快一次测量误导。
23. 作为项目负责人，我希望失败、取消和未就绪样本也留在报告，以便成功样本均值不掩盖问题。
24. 作为维护者，我希望测量记录设备、网络和缓存层状态，以便结果可以复跑比较。
25. 作为维护者，我希望浏览器功能测试与真实渲染性能环境分开说明，以便禁用GPU的检查不误导选型。
26. 作为研究者，我希望优化前后同条件数值和几何可核对，以便速度不能抵消错误。
27. 作为维护者，我希望每轮只改变可解释的技术因素，以便知道收益来自哪里。
28. 作为维护者，我希望缓存按字节和版本设总预算，以便跨日期或任意窗口访问不会无限增长。
29. 作为维护者，我希望可再生缓存与原档、分析输入和保存结果分开，以便清理不误删研究资料。
30. 作为维护者，我希望获得现服真实CPU、内存、磁盘和服务清单，以便判断资源是否不足。
31. 作为项目负责人，我希望区分演示、东海多年研究与全球冷归档，以便“完整数据”有明确容量口径。
32. 作为维护者，我希望容量包含解码数组、临时空间、worker和任务并发，以便不以压缩文件大小估算运行内存。
33. 作为项目负责人，我希望先比较保留现服和针对性扩容，以便避免无依据采购。
34. 作为维护者，我希望受控基准不会影响生产使用，以便排查本身不会制造事故。
35. 作为研究者，我希望论文方案与普通方法对照，以便知道增加复杂度是否值得。
36. 作为研究者，我希望联动聚合记录构建与更新成本，以便热查询变快不掩盖整体成本。
37. 作为研究者，我希望空间桶和图像仍遵循圆域边界及缺测合同，以便优化不悄悄改变分母。
38. 作为维护者，我希望格式与渲染器实验从小切片开始，以便不必先迁移全历史数据。
39. 作为项目负责人，我希望每个候选都有采用或放弃理由，以便后续工作不围绕未验证技术无限扩张。
40. 作为使用者，我希望归档未就绪与正常加载分开，以便知道何时需要主动准备资料。
41. 作为维护者，我希望性能和数据资格任务复用既有工作包，以便不会重复实现请求状态或审计。
42. 作为项目负责人，我希望目标未达到时知道主要原因和替代方案，以便作出具体资源或范围取舍。
43. 作为维护者，我希望成果保留版本、测量摘要和复算步骤，以便其他人能审查收益及限制。
44. 作为研究者，我希望无收益或不适用实验同样被保留，以便不把套用论文等同于算法创新。

## Implementation Decisions

### 1. 范围、事实与既有任务分工

- 本规格细化 [P1 #17](https://github.com/NingRuo-code/Ocean/issues/17)，属于 [执行总纲 #13](https://github.com/NingRuo-code/Ocean/issues/13)。已读取其最新正文和评论，仍开放、暂无评论；未据此认定实现或部署进度。
- 基线与本地测量工具可立即推进，不等待整个 P0、界面或 A 完成。真实月分析性能依赖对应 A 入口及 P0 支持合同；论文空间聚合实验依赖稳定的共同支持和计算语义。
- [#28](https://github.com/NingRuo-code/Ocean/issues/28) 承接换日/视野请求身份、过期隔离、错误分类和一次重试；P1 复用其实现并测量调度、复用和渐进收益，不再建一套相同正确性任务。原始基线允许先记录旧问题，优化准入必须解决相应错误。
- [P0规格 #35](https://github.com/NingRuo-code/Ocean/issues/35) 及 #36–#44 负责来源、有效覆盖、粒度、条件/几何和资格。P1消费这些事实，不重新裁定零值或研究粒度；合法小样可先验证性能合同，不能冒充真实完整月就绪。
- U2 首批 #33/#34 负责科学色带、图例及显示限制；活动全量/尺度聚合与 P1 联合实施。本规格不以换色或提示限制当作聚合完成，不重复修改左右面板布局。
- 已有窗口 LOD、RLE、按日期片缓存、目录缓存和PNG编码可复用。源码显示整图重建、全页签刷新、跨日期缓存和活动截断是候选成本，尚未证明哪个最大。2026-10-23单次公开接口与机器注释仅为历史证据；本轮没有新测线上性能或服务器配置。

### 2. 现服、请求链与工作集盘点

- 只读核对实际前端请求、代理/后端路由、部署/数据身份及响应来源，解释接口缺失或失败发生在哪一层。历史 viewport 404 不能直接当今天仍故障，也不能将另一条接口的快响应当本路径性能。
- 盘点CPU、可用内存、磁盘/余量、IO及带宽已知项、进程与worker、已有任务负载。没有权限或监控证据的项标未知，不用代码注释或本机资源代替现服。
- 数据按原档、在线热输入、派生/索引、缓存、结果、临时加工与备份分别计实际字节和增长；与 P0 共享来源身份。压缩、解包、数组展开和峰值处理表示分开，不由静态导出尺寸推全量。
- 明确三个容量场景：当前演示、已确认范围的东海多年联合研究、全球完整冷归档上界。全球场景不授权下载或纳入全部强度、SST、AIS原轨迹；来源和年份不齐时不能把名义天数当实测。
- 正常线上仅低频只读功能探针；重复、冷缓存、并发和负载实验在本地、测试实例或隔离环境执行。缺现服事实时先交付测量工具和有限结论，不阻断独立可做部分。

### 3. 测量合同与两个正确基线

- 原始行为基线 B0 保留当时已知限制，包括第60分位活动过滤和700点截断、隐藏面板计算、接口/版本差异。它用于复现现状，不能作为完整语义方案的公平速度参照。
- 正确参照 B1 对可合法使用且支持明确的小切片执行完整输入/直接汇总及目标显示语义。优化收益只能与相同资料、有效支持、条件、色标和结果要求的基线比较；工作量不同则并列报告，禁止直接声称加速倍率。
- 每份实验绑定提交/部署、资料及方法版本、设备/浏览器、窗口/DPR、渲染模式、网络条件、服务配置、输入规模、操作序列、缓存层状态、预热、重复和汇总协议。页面版本不同产生新的基准批次，不拼接有利样本。
- 冷/热分别描述浏览器HTTP缓存、应用数值缓存、服务缓存、文件系统缓存及预聚合状态。仅清某一层就写明该层冷；不能证明OS冷就标未知。不清空生产缓存或全盘缓存来制造冷启动。
- 正式协议在比较前冻结重复次数、样本选取、顺序/交错方式、分位估算、失败与超时口径、资源预算和容差；初筛与正式验收分开。样本不足以判断尾延迟时标探索结果，不以一两次请求称稳定p95。
- 附成功样本p50/p95、全部尝试数、成功/失败/取消/超时/不支持数量及超预算比例。失败不从记录中静默剔除，不将失败记0毫秒；成功样本很快也不能掩盖无法完成的操作。

### 4. 用户可用状态与分段计时

| 测量事件 | 开始与结束边界 |
| --- | --- |
| 首次可用概览 | 从页面导航开始，到该场景必需层的正确概览已呈现且地图可实际操作；底图或加载提示出现不算完成 |
| 切日期新概览 | 从用户日期动作开始，到新日期必需层概览呈现；包含调度等待、实际加载与绘制，不只测请求发出后 |
| 视野明细 | 从最后一次拖缩操作结束，到该视野所需细节呈现并可按契约查询；概览不冒充明细 |
| 点/范围/图层切换 | 从真实操作到相应有效结果呈现，保持唯一已应用条件与必要状态 |
| 月分析及图表联动 | 已验收入口被主动发起，到相同计算语义的结果可读；准备资料和新建物化成本另列，不能隐藏 |

- 已确认目标保留为已准备东海资料的首开概览≤3秒、换日概览≤1秒、停止拖缩后明细≤2秒。V0冻结这些目标对应的设备、网络、必需图层、数据规模、冷热状态与统计口径；未冻结或无测量不能宣称达标，也不能擅自降低目标。
- 关联服务排队、读取/计算、序列化、真实传输、JSON解析或图像解码、适配、绘制及面板成本。阶段可能并行，不把所有阶段耗时相加当用户总等待；诊断不足的阶段标未测，不以差值猜成确定因果。
- 浏览器记录请求/状态、实际编码与传输字节、缓存命中、长任务、帧间隔、必要节点/绘制规模和内存趋势；服务端记录可得CPU、峰值RSS、IO及缓存变化。跨时钟关联使用可匹配身份和本地持续时间，不直接相减未经同步的时间戳。
- 既有无头功能检查常禁用GPU；可用于功能回归，但真实渲染与GPU候选比较须另外记录并使用可比渲染环境。不能据软件渲染或不一致硬件得出实际GPU收益结论。
- 观测只增加诊断能力，不在产品界面堆放性能细节。计时开销需估计或以开/关对照说明；缺失的指标标不可得，不伪造为零。

### 5. 固定场景与正确性门

- 场景包含冷首开、已准备换日、同窗异日、异点/半径、图层组合、重叠和非重叠平移、局部/区域/球面缩放、长播放、面板开合、失败及快速乱序；月分析入口验收后加入月度/时间序列联动。
- 样本选普通、锋面密集、活动密集、海岸/数据边界和缺测日，注明来源和支持。缺某季节或年份真实样例就标缺项，不能将合成数据当实测季节覆盖。
- 所有候选先核对日期/资料身份、总小时及有效支持、几何/距离、侧别/缺测、图例/查点/选中行为和冻结容差。零、未知、未准备与失败不因缓存或渲染变更合并。
- 地图视野不替代分析公里圆，屏幕桶和图像不成为研究真源；ADR要求的粒度差异仍由P0处理。数值错误或关键交互损坏为硬失败，不能用平均速度改善抵消。
- 初筛对所有候选使用同一合法小切片与操作协议；正式采用再扩大到目标规模。公开结果只含允许的聚合证据，不把原始受限输入随基准上传。

### 6. 请求调度与渐进加载

- 在既有 #28 身份/错误正确性上，实现当前操作优先、在途同条件复用、防抖及并发上限；有效取消和过期隔离配合，不能等旧慢任务完成才响应新任务。
- 先概览再视野明细；同日拖缩可保留合格概览，换日保留底图/视角并隐藏旧观测。请求数量、完成顺序与必要层可用状态可观察，概览的粗尺度明确说明。
- 只有当前必需操作完成且有预算时，空闲预取前后各一天已就绪概览；不预取邻日明细、不自动准备归档、不挤占当前图层。切条件/超预算时停止或撤销无用预取。
- 日期、层、窗口/尺度、服务模式、资料/处理版本进入必要身份；过期响应可进入身份正确且未超预算的缓存，不得覆盖当前画面。重试语义复用#28，不为优化增加隐式循环。
- 评价新概览/明细实际等待、重复请求数、字节和错误比例；不能只靠减少请求把必需细节永远不加载。

### 7. 有界缓存、分级显示与绘制

- 浏览器跨日期缓存和服务缓存按全局字节、条目、并发与版本设置有据上限，包含数值、对象和图像可计部分；仅“每日期四片”或仅限制150个文件不等于整体有界。参数随工作集和测量冻结，不在本规格盲定内存常数。
- 数值缓存身份与渲染身份分开；纯界面色表变化不无谓重建原数值，图像缓存必须包含色表、标尺、局部增强及相关处理版本。源/方法变化不得复用旧资格或图像。
- 测重复平移、跨日期长播放和版本变化后的缓存增长、命中、淘汰、垃圾回收/进程资源；JS堆、浏览器/服务RSS、图像纹理和磁盘分别统计可得项，不把堆小误说总内存小。
- 只清理明确可再生且在目标范围内的缓存；原档、受保护案例和报告不因性能实验清理。加工/任务产物保留策略由公共运行模块负责，P1只计其预算与接口。
- 优先稳定底图、按图层增量更新、投影/路径和指标复用、隐藏面板按需计算。依赖条件和失效路径正确，重开面板能得到当前结果，不为了省计算留旧数字。
- 活动远景在明确视野支持上分桶，保存总小时、源格数、空间范围与下钻身份；取消默认第60分位过滤和700点硬截断。近景恢复视野内完整有效格，聚合尺度显式标识，颜色/大小沿用已确认跨日固定规则。
- 守恒核对针对同一支持上的原有效输入与聚合输出；球面背面、裁切和预取余量与实际视野分开。不能要求屏幕上所有圆点之和等于整个返回批次，更不能从桶推算完整分析圈。
- 全量/聚合正确后才比较绘制成本；若SVG仍是主瓶颈，再试Worker、Canvas/WebGL等限定方案，保留查询/选中/键盘/触控及图例。不先替换地图框架，也不新增平滑模式伪造精度。

- Zarr只针对实际时空查询比较分块布局，记录格式/实现版本与更新代价；不将全历史转换作为近期地图或A分析前置。[Zarr官方项目](https://zarr.dev/)
- V3a栅格/时空读取与V3b联动聚合独立，均不阻塞V1/V2近期修复。进入实验前核对原论文/官方实现版本、假设及本项目适配点；新发现若不符合当前架构就明确延后，而非扩张成全套必做技术。

### 9. 容量决策、资源预算与准备资料

- 容量报告分别列事实、测量、推算和未知项。对每个已声明资料规模与工作量，核算在线工作集、原档保留、派生/索引、全局缓存上限、加工暂存、结果与备份及增长余量；余量系数说明依据，不称软件最低要求。

- 对照保留现服、减重复工作/限并发、分离冷热资料、增磁盘/带宽或CPU/RAM等有针对性的方案。候选配置未经同负载测试只能标估算，不能把旧4核16GB等建议当当前机器或必需最低配置。
- 当缺少某规模样本或现服清单，交付公式、测量缺口和适用限制，不能可靠声称“完整数据需要某配置”。升级建议若涉及费用，准备具体方案后另行确认；本规格不采购或迁移。
- 已归档未在线准备与正常地图加载分开。PERF-04a 的一键准备仍保留在总体规划，由可访问归档合同和公共任务模块承接；P1提供工作集、字节/并发/暂存预算和测量，不重复实现完整排队/恢复/取消系统。准备后仍由用户主动发起详细分析。

## Testing Decisions

### 1. 已确认的主要验证入口

以现有浏览器端到端操作为主入口，扩展真实导航、换日、拖缩、图层、面板和播放场景的计时与资源采集；同一操作批次联结必要服务诊断、数据参照和容量报告。优先复用现有Edge/CDP交互能力，不新增一套业务测试API或只测内部函数调用速度。

用户已于2026-10-24确认“按上述边界验收并发布（推荐）”：以真实操作的完成时间与正确性为主，同语义对照、冷热分布、长时资源及受控服务测量作证；模拟/本地、测试环境和生产探针分开报告，容量依据实测工作集，未验证不宣称达标。此前界面和P0验证继续有效，不等同于P1性能验收已完成。

### 2. 好的测试与现有基础

- 测试可见状态、资料身份、真实数值、请求和资源边界；计时围绕用户动作到完成，而非内部函数是否被调用。保留地图、图例、选中、查点、键盘/触控及离线回归。
- 现有浏览器交互与布局检查可复用；后端已有窗口合同、缺资料不报零、缓存版本和清理范围检查；数据检查与P0输出提供正确性参照。增量扩展，不为每种候选引入独立业务合同。
- 功能检查可用受控响应复现乱序、超时和缺测；真实性能必须测实际被声明的服务/编码/浏览器路径。不能用内存假接口或本地文件速度证明线上性能。
- 计时工具也须验证边界：已知延迟能被计入、旧响应不会提前触发完成、空白底图不被识别成可用概览、统计汇总可由原始测量摘要复算。

### 3. 必须覆盖的验证矩阵

| 方面 | 验证要求 |
| --- | --- |
| 首开/换日/拖缩 | 正确日期/视野、可用概览/明细定义成立；调度等待和绘制计入 |
| 冷热与失败 | 分缓存层、预热和样本数，保留全部尝试；失败不能变成0或消失 |
| 正确参照 | B0限制显式，B1同输入/支持；总小时、面积/日期、几何和缺测一致 |
| 调度/预取 | 当前请求优先，在途复用；只邻日就绪概览，不触发归档；错误语义复用#28 |
| 长播放/多窗口 | 全局内存、缓存字节/版本和并发受控；旧版本不串，淘汰后可合法重取 |
| 绘制/面板 | 几何与读数保持，隐藏面板不拖交互，重开后更新；真实渲染环境可比 |
| 活动聚合 | 同支持小时守恒、远景下钻、近景完整；无分位/700点默认截断，统计真源独立 |
| 栅格与替代渲染 | 查点/选中/图例和缺测保留；编码/传输/解码/绘制综合成本对照 |
| 联动聚合 | 普通参照、优化开关、构建/更新/退回；圆域边界及分母不因桶改变 |
| 容量 | 实际规模、峰值和增长有证据；原档/热数据/缓存/暂存分开；无硬件事实不作已验证配置结论 |
| 环境边界 | 生产只读探针、测试隔离、无生产缓存清空；基准与受限资料不外泄 |

### 4. 交付证据与完成状态

- 每份报告保留执行/资料/方法版本、场景及原始测量摘要、正确性参照、冷热与重复协议、资源、失败及采用结论。数字能回溯到运行，不只提交截图或汇总均值。
- 应用改动运行相应数据、交互和布局检查；后端改动按仓库要求完成检查。每轮性能复测与其实际改变对应，不在没有新变化时无意义重跑全套。
- 本轮仅整理规格、核对仓库与原始方法来源；没有运行新基准、并发实验、现服资源清点、购买、合并或部署。文件格式/链接检查通过不等于性能目标达标。
